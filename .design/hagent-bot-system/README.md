# hagent bot · 通用平面角色动效系统 · 转向修订

设计评审稿 · 2026-09-07。交付范围仍为设计规范与独立交互样片，未接入产品。以第二版的二维平面风格为基础，仅修正转向时的体量表达；[第二版存档](v2/index.html) 供对比。

[打开交互样片](index.html) · [查看验证记录](VALIDATION.md)

## 1. 本轮设计决定

本系统面向通用 Agent：聊天助手、编程助手、研究助手、自动化执行器等可以共用相同角色、状态和动作。产品只提供“现在处于什么状态”，不把领域术语、业务对象或工具图标放进角色引擎。

**状态由方块本体承担：轮廓形变 + 重心移动 + 转身 + 双眼 + 时序。** 所有右下角角标、对勾、感叹号、暂停符号、放大镜、笔、纸张、外置节点都已从新版角色资产中移除。方块不会变成文字、标点或另一枚业务图标。

**彩带是运动的痕迹。** 借鉴 Grok Bot 的彩色绕行与拖尾，为 hagent 独立绘制带有前后遮挡、粗细渐变和余韵的轨迹；在转身、推进、接收、发送和庆祝时强化动量。它不充当状态徽章，也不通过红黄绿来编码结果。

保留 **24 个通用持续状态、8 个事件动作、4 个微表情**。每个状态都有独立的身体动作定义。样片可关闭彩带，直接比较本体；可同时观察六种不同运动逻辑，而不必只看放大的单一状态。

## 2. 本轮转向修正

本轮撤下真实三维模型、WebGL、材质光照、地面投影和观察视角控件。继续使用 SVG 平色角色，默认待命正面，观察角偏移为零。原有 36 项通用动作和彩带保留。

转向采用二维绘制规则：正面占比逐步收小，侧面纯色区域补上它让出的面积；整体宽度只在 100% 至 90% 之间变化，侧向仍是一枚饱满方块。双眼贴在可见正面区域，随正面横移并受裁切，侧向与背向完全隐藏。回正后侧面区域收为零，恢复单一平色方块。

侧面只用相邻的低对比纯色，不使用渐变、高光、投影或真实光源；彩带仍保留独立的彩色渐变。这套画法表达角色厚度，不把图标做成三维物件。

样片新增正面、45° 转向、90° 侧向、180° 背向四个静态分解。这些角度是动画进度的参数，不是三维相机角度。

### 延续第二版的设计决定

| 第一版问题 | 第二版决定 |
|---|---|
| 很多状态依赖角标辨认，身体变化不足 | 移除整套角标与道具层；重写 36 个条目的身体动作 |
| 缺少 Grok 式彩色环绕点缀 | 新增独立彩带层；前后分层、弧线拖尾、收放与消退 |
| 状态、身份与触发条件偏向特定业务 | 核心定义只接受通用状态；身份样本改为可替换色板；情境采用通用任务流程 |
| 工作态之间多为类似的轻微移眼 | 从运动轴区分：横向收合、向下承接、向上推出、扭转、推进、舒展、收紧对齐 |
| 完成、受阻、失败依赖符号 | 分别用舒展站稳、侧向受压、向下卸力建立轮廓差异 |
| 增加了很多条目，但不容易横向比较 | 增加六种动作的同步对照、彩带开关、半速回放 |
| 部分切换在暂停/重播后的零时间帧直接跳到新姿态 | 只有首次创建与减少动效才直接采用代表姿态；正常切换保留当前值与速度 |

## 3. Grok 参考依据

- [官方设计说明](https://x.ai/news/designing-grok-bot)：采用一致的简单形体与有表现力的双眼，让角色承担工作状态。本方案延续角色本身表达状态的思路。
- [ngocdevv/grok-bot-emoji](https://github.com/ngocdevv/grok-bot-emoji)：README 及 `grok-orb-scene.tsx` / `grok-orb-trails.tsx` 展示前后分层的彩色轨迹与宽度变化。研究其轨迹组织思路；本版使用独立的 SVG 方块、路径与运动参数。
- [blessonism/grok-icon-study](https://github.com/blessonism/grok-icon-study)：第一版产品引擎注释标明的参考源。研究已有的弹簧、姿态、眼形和 ribbon 前后分层；该仓库注明提取素材仅供学习，因此本次没有新增提取素材或复制角色几何。

第二版的状态分类、动作句、强度、周期和彩带造型均为本次设计，不能称为 Grok 官方规范或像素级移植。项目不引入 Skia、React Native 或新动效依赖。

## 4. 造型母版与形变范围

### 4.1 不变的身份

100 × 100 逻辑坐标。本体正常边界 `(14,14)` 至 `(86,86)`；圆角切入量为边长的 22.4%。双眼中心 `(40,46)` / `(60,46)`，正常宽 8、高 18。眼形采用同一组闭合曲线控制点，支持眯眼、张眼、斜眼与弯眼。

本体始终是四角圆润的实心方块。无嘴、无永久手脚、无道具。形变可以改变两肩高度、上下宽度、侧向倾斜与整体压缩；眼睛随脸部平面转动，在侧身时变窄，转到背面时弱化。完成转身后还原同一身份。

### 4.2 六个表达通道

| 通道 | 表达内容 | 约束 |
|---|---|---|
| 重心 `x / y` | 探寻、承接、推进、后撤、落定 | 日常位移通常不超过 7 逻辑单位；庆祝短跃不超过 10 |
| 姿态 `roll / yaw` | 侧靠、转身、半转暂停、回旋 | 日常侧倾 ≤12°；yaw 用于平面转向进度与眼睛可见性，不让人物变成旋转加载器 |
| 体量 `scaleX / scaleY` | 蓄力、承重、卸力、舒展 | 日常约 0.82–1.17；休息可更低伏；小尺寸降低变化幅度 |
| 轮廓 `top / bottom / lean / shoulder` | 受压、扭身、非对称完成 | 四角拓扑不变，不拼出对勾、问号或其他状态符号 |
| 双眼 | 注意力、专注度、完成感 | 双眼可异步变化；眨眼不由流式分片驱动 |
| 彩带 | 方块动作的方向、速度与余韵 | 有后层与前层；无独立语义；关闭后身体动作完整 |

本体默认中性墨色，深色主题反转为柔和浅墨。身份色可替换，状态改变不会使身体自动变红或变绿。彩带不改变角色身份色。

## 5. 彩带设计规范

### 5.1 形态

彩带是一段有长度、有头尾的曲线，不是完整闭合的加载圆环。每条沿二维椭圆轨迹绘制，按深度拆为两层：后段在身体下面，前段在身体上面。前段经过腰部或轮廓附近，尽量让双眼保持清楚。

首端与尾端收细，内部较宽；以连续轮廓绘制，避免许多相邻小四边形产生抗锯齿接缝。青 → 蓝 → 紫 → 粉 → 金的渐变是装饰语言，不能把颜色解释为成功、失败或某个业务对象。浅色主题适当压低亮度，深色主题提高明度。

默认 1–3 条；普通工作多数 2 条；协同与庆祝最多 3 条。大尺寸每条边缘约 54 个采样间隔，小尺寸约 30。单条最大半宽约 2 逻辑单位。绕行半径约 51–57，中心略低于身体中心，避免主要视觉落在眼睛上。母版以外的轨迹需要容器预留安全空间。

### 5.2 按身体动作组织轨迹

| 轨迹 | 对应动作 | 设计规则 |
|---|---|---|
| 缓慢绕腰 | 思考 | 双带在不同倾角上缓慢绕行，身体慢扭转；少量停顿感，避免高速旋转 |
| 紧凑推进 | 执行 | 跟随压缩—推进节奏，轨迹紧凑，速度比思考快 |
| 交织舒展 | 生成 | 两条反倾角曲线，随身体左右舒展交织 |
| 换边穿行 | 协同 | 最多三条不同相位的线，身体左右反向扭转；不增加外部小头像或节点 |
| 聚拢 | 连接 / 恢复 | 两条弧线逐渐接近身体，身体同时收合再打开 |
| 向内承接 | 接收 / 接住 | 半径收小，方块接住动量并下沉 |
| 向外释放 | 发送 / 派发 | 半径展开，配合身体向上推出或向侧面拧身 |
| 回卷 | 重试 | 轨迹方向反转，与后撤—蓄力—再试形成同一句动作 |
| 归拢消退 | 收尾 | 振幅、转速和亮度逐渐收小，约 3.4 秒内安定 |
| 短弧 | 阶段进展 | 一条弧跟随抬角动作划过，立即退场 |
| 三带回旋 | 庆祝 | 三条彩带随跃起、转身展开；落地后逐步消退，不长期环绕完成态 |

无彩带状态：待命、倾听、规划、搜索、阅读、检查、等待、等待回应、受阻、完成、部分完成、失败、已停止、暂停、休息，以及不需要轨迹的微表情。

### 5.3 生命周期

普通换态时轨迹相位不重置。数量、倾角、长度与强度连续过渡。工作被打断后彩带在约 160–240ms 内收掉；身体尽快进入需要回应/故障姿态。紧急语义文字立即更新，不等彩带结束。

小于 48px 默认关闭彩带；48–64px 保留细带，降低视觉权重；大尺寸可完整表现。减少动效时全部退场，使用静态本体。预览中的“彩色拖尾”开关只用于评审，产品可用统一 motion 配置控制。

## 6. 通用持续状态全集（24）

每个条目的名称、动作说明和关键姿态均在样片中可见。没有外置状态符号。

| 标识 / 中文 | 本体动作 | 眼神 | 时序 / 触发 |
|---|---|---|---|
| `idle` 待命 | **重心微移**：方块微微换重心，眼神偶尔游移，始终留在原位。 | 柔和双眼；偶尔侧看 | 8 秒长节奏；没有活跃工作 |
| `listening` 倾听 | **前倾探身**：上半身向输入方向探出，底部留在原位，像认真侧耳。 | 双眼张开，注视一侧 | 3.8 秒；前倾后停留；用户输入或真实的监听状态 |
| `connecting` 建立连接 | **横向收合**：两侧向内收，随后展开；第二拍比第一拍更接近完整方形。 | 目光从两侧回到中央 | 2.8 秒；收合—展开；连接正在建立 |
| `receiving` 接收 | **向下承接**：方块接住一股向下的动量，轻压后回弹，重心随之落下。 | 视线从上落到中央 | 2.8 秒；承接—回弹；正在接收输入、数据或结果 |
| `sending` 发送 | **向上推出**：先压低，再向上伸展，把动量送出去；身体随后回收。 | 视线先抬起，动作后跟上 | 2.6 秒；蓄力—推出；正在发送数据或消息 |
| `thinking` 思考 | **悬停扭转**：身体慢慢扭向一侧，再悬停转回；彩线顺着转身绕过腰部。 | 一眼收窄，目光略向上 | 5.2 秒；慢转—悬停—回转；显式思考或推理阶段 |
| `planning` 规划 | **三段落点**：方块依次倾向左、中、右三个稳定落点，最后把自己摆正。 | 视线先到下一个落点 | 3.6 秒；三段落点；显式计划与安排阶段 |
| `searching` 搜索 | **左右探寻**：身体侧转探出，停一下，再去另一侧；横向行程清晰可见。 | 宽眼寻找，眼神先于转身 | 3.2 秒；探左—停—探右；正在寻找信息或目标 |
| `reading` 阅读 | **逐行下沉**：方块很轻地顺着行进方向倾斜；行尾复位，再小幅下沉。 | 从左至右，回扫换行 | 3 秒；横扫—回扫—换行；顺序消费文本、图像或内容 |
| `working` 执行 | **弹性推进**：底部撑住，身体压缩向前推进，再弹回准备下一拍。 | 双眼聚焦，注视前下方 | 2.2 秒；压缩—推进—回弹；工具或计算正在执行 |
| `generating` 生成 | **左右舒展**：身体左右交替舒展，像有节奏地织出连续内容。 | 双眼随左右节奏交替聚焦 | 2.6 秒；左展—右展—停顿；正在生成内容或持续输出 |
| `verifying` 检查 | **收紧对齐**：方块先横向收紧，再纵向拉直，最后严格回到中轴。 | 双眼同时眯起，再恢复平齐 | 3 秒；收紧—对齐—停顿；正在验证、评估或复核 |
| `coordinating` 协同 | **交替扭身**：上、下半身形成轻微反向扭转，随后换边，带动两条交错轨迹。 | 轮流关注两个方向 | 3.8 秒；换边扭转；正在协调多个活跃工作单元 |
| `waiting` 等待 | **侧靠停留**：方块向一侧轻靠，双眼放松；等候时留在这个重心。 | 半开双眼，安静侧望 | 6 秒；只轻移一次眼神；已知外部依赖正在等待 |
| `awaiting-input` 等待回应 | **挺身注视**：先直起身，再向前探一点；双眼看向用户，保持这个姿态。 | 正面睁眼，注视用户 | 360 毫秒进入后保持；需要用户输入、选择或确认 |
| `blocked` 受阻 | **侧向受压**：方块向右尝试推进，仿佛受到阻力，侧面被压住后停下。 | 一眼收紧，一眼留意阻力 | 480 毫秒进入后保持；确定的障碍使工作无法继续 |
| `retrying` 重试 | **撤回再起**：先略向后撤，把身体重新拧紧，再沿原方向试着起步。 | 回望一下，再重新聚焦 | 3.2 秒；撤回—蓄力—再试；真实重试已开始 |
| `settling` 收尾 | **归拢安定**：大幅动作逐步收小，身体从轻扭转归正；彩带顺势收拢。 | 眼神回中，逐渐放松 | 3.4 秒后安定；仍可保持此态；工作进入最终整理阶段 |
| `completed` 完成 | **舒展站稳**：向上舒展一次，双眼弯起，落在高而端正的姿态。 | 对称的满意眼形 | 600 毫秒进入后保持；工作已经成功结束 |
| `partial` 部分完成 | **非对称舒展**：身体一侧已经舒展，另一侧仍略收着，保留未完全落定的形状。 | 一眼柔和，一眼保持注意 | 420 毫秒进入后保持；部分结果就绪，仍有未完成部分 |
| `failed` 失败 | **向下卸力**：力气卸下来，上缘略低、底部变宽；身体稳住，不再试着推进。 | 双眼稍低，仍然清醒 | 480 毫秒卸力后保持；本次工作已失败并结束 |
| `cancelled` 已停止 | **回收刹停**：向前的动量被收回，身体短暂后坐，再回到较低的稳定姿态。 | 中性横眼，视线回中 | 450 毫秒刹住后保持；明确的停止或取消已经确认 |
| `paused` 暂停 | **半转悬停**：保持一半转身，身体收窄，像把动作暂时留在空中。 | 双眼半开，方向仍保留 | 240 毫秒收束后保持；工作明确暂停，可继续 |
| `sleeping` 休息 | **低伏合眼**：身体柔软地压低，靠向一侧，眼睛合成两条弧线。 | 完全闭眼 | 600 毫秒进入后保持；明确休息或非工作展示 |

## 7. 单次动作与微表情

事件是发生了一件事；持续态是当前正在做什么。两者分开，避免把短促庆祝当作持续完成状态。

| 标识 / 中文 | 本体动作 | 眼神 | 时序 / 触发 |
|---|---|---|---|
| `appear` 出现 | **展开成形**：从紧凑的小方块展开，双眼随身体睁开，落定。 | 从合眼到睁眼 | 600 毫秒；新角色首次出现 |
| `acknowledge` 收到 | **短促点头**：眼睛先回应，方块前倾并点一下头，回正。 | 正面注意 | 480 毫秒；输入被确认接收 |
| `dispatch` 派发 | **拧身甩出**：方块向右拧身再回弹，彩线随这个甩动向外舒展。 | 先看派发方向 | 720 毫秒；一次真实工作派发 |
| `receive-result` 接住 | **侧身承接**：侧转迎向来处，身体压下接住，再舒展回中。 | 迎向来处，再回正 | 680 毫秒；一个结果返回 |
| `milestone` 有进展 | **轻抬一角**：一侧肩角轻抬，身体转出短弧，再继续工作。 | 短暂满意 | 680 毫秒；有意义的阶段进展 |
| `notify` 注意到了 | **挺高回落**：方块短促挺高，双眼放大，然后带一点弹性落回。 | 双眼同时张开 | 640 毫秒；明确的新信息提醒 |
| `recover` 恢复 | **解压复位**：受压的身体释放开来，先宽后高，沿顺滑轨迹回正。 | 重新聚焦 | 820 毫秒；收到真实的恢复证据 |
| `celebrate` 庆祝 | **跃起回旋**：预压、跃起、转身，三条彩带绕着身形展开，再收进满意的落定。 | 转身时收眼，落定时弯眼 | 1400 毫秒；被见证的一次成功 |

| 标识 / 中文 | 本体动作 | 眼神 | 时序 / 触发 |
|---|---|---|---|
| `blink` 眨眼 | **自然开合**：快速合拢，短停，再自然睁开。 | 同步开合 | 220 毫秒；自然眨眼 |
| `glance` 看一眼 | **视线先行**：眼睛先动，头部轻跟随，再回正。 | 侧看回正 | 720 毫秒；局部注意力变化 |
| `curious` 好奇 | **歪身打量**：一边肩角抬起，身体轻歪，双眼一大一小。 | 不对称张眼 | 1000 毫秒；待命时的稀疏表达 |
| `content` 会心 | **轻松舒展**：身体略向上松开，双眼柔和弯起，回落。 | 轻微笑眼 | 900 毫秒；明确的积极回应 |

出现、派发、进展、接住、恢复、庆祝只在真实事件发生时播一次，并按事件 ID 去重。事件结束后回到最新持续态；不回到触发前缓存的旧状态。重要工作/人工介入可以打断事件。六动作对照区为了比较，会有意循环重播“庆祝”；这不是产品事件调度规则。

## 8. 容易混淆的状态怎样区别

| 状态组 | 本体层面的区别 |
|---|---|
| 接收 / 发送 | 接收向下承重、变宽变矮；发送蓄力后向上伸展、变窄变高。关闭彩带仍保留方向与体量差 |
| 思考 / 规划 | 思考是连续而缓慢的视角扭转；规划是三个有稳定停留的身体落点 |
| 搜索 / 阅读 | 搜索是明显左右探出并转身；阅读几乎原位，以小幅倾斜和换行下沉为主 |
| 执行 / 生成 | 执行有底部着力的压缩推进；生成左右交替舒展，身体两侧此消彼长 |
| 检查 / 思考 | 检查沿中轴收紧、拉直并归正；思考保持不对称眼形和悬停扭转 |
| 协同 / 执行 | 协同左右换边扭身，执行沿一个方向推进 |
| 等待 / 等待回应 | 等待侧靠、放松双眼；等待回应正面挺高，双眼张开看向用户 |
| 受阻 / 失败 | 受阻侧向受压，仍带尝试方向；失败卸力变宽变矮，停止推进 |
| 失败 / 休息 | 失败清醒，眼睛低但睁开；休息明显低伏侧靠、完全闭眼 |
| 完成 / 部分完成 | 完成两侧对称舒展、双眼同弯；部分完成一侧抬起，一眼仍保持关注 |
| 暂停 / 已停止 | 暂停保持半转身与原方向；已停止把动量收回，回中并降低重心 |
| 重试 / 建立连接 | 重试先后撤再起步；建立连接横向收合再打开 |

这些是设计上的区分依据，不声称所有用户初见就能在 20px 准确猜中 24 个状态。小尺寸仍配邻接状态文字或可访问名称；文字不画进角色，也不转换成角标。若真实辨识测试仍混淆，优先修改身体与节奏，而不是加符号补丁。

## 9. 切换与动作编排

### 9.1 优先级

当前工作已确认的终态/故障、人工介入 → 真实工作态 → 事件反馈 → 局部注意力 → 待命微表情。仲裁以当前任务 ID 与可信事件为准。旧任务的迟到结果不覆盖新任务，未得到实际成功信号就不能庆祝。

### 9.2 衔接

- 相同状态的新分片只更新参数，不重新起动作，不排眨眼。
- 普通工作候选稳定约 180ms 后切换，当前动作最低展示约 600ms；高优先级回应/故障/停止绕过此驻留。
- 姿态、轮廓、眼形从正在显示的值与速度继续。旋转角度采用连续角度处理，避免接近 360° 时突然反向回零。
- 眼神通常先于身体 40–70ms；身体先于彩带形成可见牵引。短促动作不能被身体弹簧过分拖慢。
- 重要状态到来时，先收住工作动量，再形成新姿态；不必先退回待命。
- 完成后的新任务立即打断庆祝。关闭窗口、离开页面、隐藏头像不代表取消工作。
- 暂停预览冻结当前帧；减少动效显示静态代表姿态；这两个功能含义不同。
- 角色离屏或文档隐藏时暂停绘制，回来不补跑漏掉的动画。事件是否已过期由业务调度决定。

### 9.3 动效起点

沿用项目已有的 120 / 200 / 320ms 小反馈节奏作为接入起点。单次表达 220–1400ms，持续状态多数 2.2–6 秒。大多数动作有明显停顿，不使用恒定速度的循环替代角色行为。

样片弹簧以角频率约 20（身体）、30（眼形/视线）、65（眨眼）为起点，身体压缩与垂直位移阻尼比约 0.83，其余约 0.96。后续框架移植必须检查参数单位，不能把频率当 stiffness。方块旋转可以短暂回弹，等待回应/故障的最终姿态必须稳定。

## 10. 尺寸、主题与无障碍

| 尺寸 | 本体处理 | 彩带 |
|---|---|---|
| 16–24px | 保留主轮廓与双眼，扩大最小眼宽；位移/倾角降至约 0.34 倍，体量差至少保留 0.6 倍 | 关闭 |
| 32–40px | 位移/倾角约 0.55 倍；保留受阻、暂停、失败等关键轮廓 | 关闭 |
| 48–64px | 完整身体动作；周期不因缩小尺寸而加快 | 细带，最多 3 条，仅对应状态出现 |
| 96–128px 及展示尺寸 | 完整轮廓、视角和事件分镜 | 完整拖尾与回旋，预留安全边界 |

轨迹的正常安全边界约为母版外侧 12 个逻辑单位；布局必须显式预留。小尺寸关闭轨迹后不再为彩带保留空洞。状态文字不随身体变形，按钮命中框也不随身体位置变化。

默认身体使用中性墨；身份可从经过主题校正的色板选择。身份配色与状态解耦。深色主题采用浅色身体/深色眼睛；彩带在两种主题分别校正明度。无需用颜色识别状态。

`prefers-reduced-motion` 动态生效：关闭所有持续动作、旋转、跳跃与彩带，直接使用代表姿态。相近状态仍有独立中文标签。头像旁有业务文字时 SVG 可 `aria-hidden`；独立头像使用可访问名称。播报使用单一业务状态区域，不能每一帧或每个 token 播报。

键盘焦点、触屏命中区域与 hover 分离。原生按钮承载操作；装饰角色本身不增加神秘的点击行为。局部指针跟随只适用于待命主角色，不能让所有子头像同时盯鼠标。

## 11. 通用接入契约

角色核心不引用特定产品 store、路由、SSE、文件类型、任务模型或工具名字。建议接入面：

```ts
interface AgentAvatarInput {
  state: AgentState;
  identity: { id: string; ink?: string };
  event?: { id: string; kind: AgentCue; taskId: string };
  attention?: { x: number; y: number };
  presentation: {
    size: number;
    motion: "full" | "reduced" | "static";
    ribbons: boolean;
    visible: boolean;
  };
}
```

`AgentState` 与 `AgentCue` 对应本规范目录。一个适配器把产品事实转为上述输入；另一个角色引擎负责动画；产品 UI 保持文字状态、按钮与错误说明。适配器替换后，母版、彩带和动作无需重画。

- 传入状态必须来自可信生命周期。没有消息不自动判为受阻，没有成功证据不自动判为完成。
- 工具执行、内容生成、结果接收可以映射到通用语义；核心不读取工具正文猜情绪。
- 多任务并行时由适配器决定主角色当前在执行还是协调；角色不倒扫业务时间线。
- 可恢复故障用 blocked；已经失败并结束用 failed；真正开始再次尝试才用 retrying。
- 未知工作细节可以回退 working；没有工作则 idle。不能用相近但未经证实的状态冒充真实进度。
- 第一版的 uploading 可按实际方向归 sending；parsing 由产品含义归 reading 或 working；writing→generating；reconnecting→retrying；delivering→settling。领域细节留在产品文字中。
- 主/子角色共享母版与动作定义。子角色仅调整强度、可见性和身份色，不另造“某行业专用形态”。

## 12. 表现层与性能设计

使用 SVG + 程序化弹簧；无需增加新动画框架。独立身体路径、转向侧面、正面裁切窗口、面部组、彩带后层和彩带前层。身体 transform 与眼形分开，彩带渐变颜色走主题 token。

彩带使用连续轮廓，按深度段分组。第一轮样片使用相邻四边形试绘出现细接缝，现已改成连续带状边缘。与全屏滤镜相比，更容易控制节点数与重绘范围，但 SVG 路径动画仍有主线程成本，不能宣称全部走合成层。

一个共享 rAF 调度可见角色；静态、离屏与终态在落定后不持续绘制。样片用 IntersectionObserver 暂停离屏实例；产品中还需把事件过期、任务 ID 和真实状态恢复纳入调度。大量头像默认弱化动作，只让当前关注的角色完整运动。

所有监听、观察器、rAF、事件槽与定时器在销毁时清理。正常状态切换不重建 SVG，不反复创建渐变 ID。多实例的渐变 ID 必须唯一。
