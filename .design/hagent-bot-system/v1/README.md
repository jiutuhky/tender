# hagent bot 角色与动效设计系统 · 01

日期：2026-09-07。阶段：设计评审，尚未接入产品。适用：Prose 主智能体、可选子代理头像、会话与任务状态。

交付：打开同目录 [index.html](index.html) 查看交互样片；本文件是状态语义、动作编排和后续实现的完整规范。样片中的任务、进度和角色均为演示数据。

## 1. 设计结论

保留现有圆角方块，将它做成一个专注、敏捷、有回应的标书工作伙伴。用眼睛表达注意力，用身体表达工作节奏，用一个小标记补充业务含义。任何工作状态都保留方块与双眼的身份。

系统分为 **24 个持续状态 + 8 个事件动作 + 4 个微表情**。数量用于覆盖生命周期；同屏通常只让一个主角色充分运动。大部分日常时间保持低振幅，收到任务、遇到阻碍、交付结果时才出现清晰的动作句。

确认重点：方块与双眼的造型、状态动作的辨识度、工作期的活跃程度。具体接线在设计确认后进行。

## 2. 当前实现审计

以下是当前工作区的事实；已有未提交改动按当前内容检查。本轮没有修改产品源码。

| 发现 | 依据 | 设计决定 |
|---|---|---|
| 已有 39 个枚举，生命周期、情绪、道具、特技混在同一状态轴 | `frontend/lib/bot/tables.ts` 的 GROUPS / EYE_PLAYLIST | 分离持续状态、事件动作、微表情；清理业务侧的表现型命名 |
| 思考、输出、上传等会进入覆盖层；本体路径可变成圆或笔形，身份和动作符号交替出现 | `fx.ts` 的 KIND / P_BLEND；`character.ts` 的 `_paint` | 工作过程中保留方块与双眼；道具只作为辅助层 |
| 主头像在 MessageWindow 接入；当前 AgentBoard 已改用任务状态图标，未消费子代理 Bot 派生函数 | `MessageWindow.tsx` 的 WindowBot；`AgentBoard.tsx`；`derive.ts` | 主头像为首要落点。子代理角色家族先设计，是否放回看板作为独立产品选择 |
| `done` 派生为 idle，但 WindowBot 确实另播 1900ms celebrate | `deriveMainBotState`；WindowBot 的 once / onceKey | 保留收尾反馈，补持续完成姿态；庆祝用本轮唯一事件去重，历史完成不重播 |
| 主状态按末尾消息倒扫，不是按活跃调用集合仲裁 | `derive.ts` 的倒序循环 | 同时有检索、输出、子任务时，按父子归属与活跃集合判定，不能只看最后一条消息 |
| 工具分为检索、写入、工作；Read 与搜索归一类，校验工具无独立动作映射 | SEARCH_TOOLS / WRITE_TOOLS；`toolLabel.ts` 有 prose_validate_matrix | 区分阅读、搜索、写入、核验、交付；未知工具归 working |
| 子代理派生函数只接受 running/done；非 live 的 running 返回 bored | `deriveSubagentBotState` | 用实际运行信号表达等待/状态未知，不能把未完成解释为无聊 |
| 没有确认、部分完成、取消、重连等独立工作状态 | BotState 与 RunPhase 类型 | 设计完整；只在具备对应信号时启用，不能靠沉默时间猜测失败 |
| 状态改变会排眨眼、重置动作上下文；同状态调用也会重置 | `character.ts` 的 setState | 同语义状态更新参数而不重播；为工作子状态增加驻留与合并规则 |
| 挂载中 spawn 插播之后，同轮 state effect 会 setState；可能立即取消入场插播 | `ProseBot.tsx` 中 useEffect 顺序；setState 会清 onceTimer | 统一挂载与入场调度，基础态先确定，入场再叠加 |
| destroy 取消 rAF，但没有清 onceTimer；插播叠加时 back 可能是上一个插播态 | `character.ts` 的 destroy / playOnce | 基础态独立保存；单事件槽；卸载清全部定时器与监听 |
| reduceMotion 在构造时读取；paused 仍调度 rAF，没有可见性挂起 | `character.ts` 的构造与 `_tick` | 动态监听偏好；静止与离屏停止逐帧循环；减少动效采用独立语义姿态 |
| 身份色与 size 等主要只在构造时传入，后续 prop 改变没有完整同步 | `ProseBot.tsx` 的 effects | 身份、尺寸、主题、强度为独立可更新通道 |
| 标题栏另有 busy 光圈、窗口光束，叠加角色动作可能争抢注意力 | `globals.css` 的 cv-bot-halo / cv-beam-breathe | 角色成为头像位置的主动反馈来源；同一位置只保留一套周期节奏 |

浏览器观察：现有 `/botprobe` 能呈现方块双眼及 39 态选择；思考态会变为三点。性能和所有旧态的真机表现尚未做全量测量，以上代码隐患不等于均已在浏览器复现。

## 4. 角色造型规范

### 4.1 母版

统一 100 × 100 设计空间，外部布局框固定。本体在 `(14,14)`，宽高 72，圆角 16.13（本体宽度的 22.4%，继承品牌比例）。正面视觉中心 `(50,50)`。常态正立，身体倾斜由动作产生。

眼睛中心为 `(40,46)` / `(60,46)`，常态宽 7.6、高 18。闭眼保留可见横缝；专注态上眼睑略斜；完成态弯成向上拱的双眼。眼形使用一致控制点拓扑，避免路径数不同导致跳变。

双眼是主要表情区域，无嘴、无独立眉毛、无永久手脚。保留眼间留白。体量变化以近似等面积 squash/stretch 为主，日常最大 3%，事件最大 7%；不把整体尺寸呼吸当作所有状态的默认动作。

本体的深浅使用现有 `--pb-ink-2` 和 `--pb-eye`。细节以平色为基准；不增加胶囊玻璃、高光球或硬质金属反射。静态首帧包含双眼，水合后形体位置与比例一致。

### 4.2 渲染层

从后到前：身份本体 → 面部视线 → 眼睑/眼形 → 任务辅助标记 → 一次性强调。身体动、视线动、眨眼各有独立数值通道，避免几个 transform 相互覆盖。

任务道具锚点在右下区域，允许在预留的 100 × 100 框内少量越出本体。状态辅助标记与任务道具共用位置，互斥显示。完成/异常标记优先；禁止同时堆“旋转环＋进度环＋粒子＋状态点”。

角色全部绘制留在固定边界内。工作态不越过布局框；庆祝仅在 ≥64px 展示区使用最大 1.12 倍视觉安全区，标题栏关闭粒子。容器预留空间，不能依赖全局 overflow:visible。

### 4.3 尺寸光学校正

| 布局框 | 用途 | 细节与运动 |
|---|---|---|
| 16 / 20 / 24px | 紧凑列表、行内身份 | 本体扩大到框的约 82%；眼宽最小 1.5px，眼高 ≥3px；不画任务道具；终态用 ≥5px 标记＋邻接文字；默认静态 |
| 32 / 40px | 标题栏、小头像 | 标准母版；眼宽最小 2px；只保留简单进度/终态标记；姿态幅度 0.55 倍 |
| 48 / 64px | 主头像、展开卡片 | 完整双眼与一个道具；日常动作 1 倍；支持局部视线回应 |
| 96 / 128px | 空状态、演示、引导 | 完整动作句；事件可上浮 5 设计单位；允许 2 个短暂亮点 |

尺寸指布局框，100 母版的 72% 是正常本体占比。不得用 128px 的效果缩到 20px 而不作裁减。小尺寸的相近工作态由邻接文字区分，不能承诺单凭 20px 双眼识别 24 种状态。

### 4.4 主从身份

主 Bot 始终中性墨色，名称沿用产品命名。子角色保留同一轮廓、眼形和比例，用可复用角色 ID 派生身份；角色 ID 不存在时才回退到 callId。配色使用经过主题校正的离散色板，不能任意 HSL 取值后固定白眼。

提案身份：文档解析（靛蓝）、商务应答（青绿）、技术应答（紫）、评分核验（赭）。每个身份同时有中文名称；≥48px 可加一个固定的极小顶部记号，≤32px 省略。身份颜色不随运行状态变化。进行蓝、成功绿、注意琥珀、失败红只用于状态标记。

当前看板未显示子 Bot；样片中的角色家族是可选设计资产，不表示本轮会把头像加回每一行。

## 5. 动作语言与参数

核心动作句：**注意到 → 做动作 → 反馈 → 安定**。眼睛先于头部 40–70ms，头部先于任务标记 30–50ms。身体遵循有阻尼的连续响应，眼形更快更稳。

沿用现有 `--t-micro:120ms`、`--t-float:200ms`、`--t-panel:320ms`、`--ease-std:cubic-bezier(.32,.72,0,1)`。以下周期是样片起点，产品接入后在实际 32/48/64px 再确认。

| 通道 | 建议范围 | 约束 |
|---|---|---|
| 视线 | 120–200ms；x ±4 / y ±3 设计单位 | 工作目标优先；不全局盯鼠标 |
| 眼形 | 160–240ms | 闭合时最薄处不消失；同拓扑 morph |
| 身体换姿 | 200–320ms | 延续当前姿态与速度；错误/确认禁止弹跳 |
| 眨眼 | 合 55ms、闭 35ms、开 110ms | 只在自然停顿时触发；工作态每 5–9s，待命 7–12s；不随 token 眨眼 |
| 阅读/搜索短周期 | 2.4–3.2s | 明确停顿，避免匀速左右摇头 |
| 工作长节奏 | 4.5–7s | 局部眼神与任务道具交错，身体大部分时间稳定 |
| 空闲微表情 | 25–45s 才有一次机会，持续 0.6–1.1s | 仅主动展示的主头像；阅读页面可关闭；历史头像关闭 |
| 事件反馈 | 260–900ms | 单次、可打断、去重，不阻塞操作 |
| 完成强调 | 720ms，最长 1100ms | 只在亲眼见证的本轮完成时播；确认有产物才庆祝 |

以角频率/阻尼比形式配置弹簧，首版建议视线 `(24,1)`、眼形 `(26,1)`、身体 `(18,0.9)`、事件挤压 `(24,0.8)`。应使用当前引擎的单位含义，不直接把频率当 stiffness。接入时沿当前显示值连续积分，若实际观感不同，以母版节奏为准。

## 6. 持续状态全集（24）

下表时长为进入 / 可见循环起点。所有状态都定义静态姿态，减少动效时保留文字和标记。

| 标识 / 中文 | 眼睛与身体 | 辅助标记 / 周期 | 触发与退出 |
|---|---|---|---|
| idle 待命 | 正面柔和双眼；偶尔移眼、自然眨眼；不持续起伏 | 无；7–12s 眨眼 | 无活跃任务；收到输入退出 |
| listening 倾听 | 双眼稍张、向输入区域轻侧头 3°；稳定注视 | 无；停顿时一次轻点头 | 用户聚焦输入并开始输入，或实际录音；失焦/发送退出；不声称当前有语音功能 |
| connecting 准备环境 | 睁眼集中，身体轻前倾后稳住 | 两个连接端点轻靠拢；3s | 创建会话/真实环境准备；进入工作或失败退出 |
| uploading 上传文件 | 目光向上追随，身体稳定 | 短箭头向上；2.4s；无真实字节进度不显示百分比 | 实际上传中；完成后 parsing/working |
| parsing 解析原文 | 逐行横扫眼神，走完一行再下移 | 纸页扫描线；2.8s；有 ingest 计数可显示页数 | ingest.progress；ingest.completed 退出；部分页失败保留注意信息 |
| thinking 思考 | 一高一低的专注眼，左上停看，回正 | 无三点替身；4.8s | thinking 增量或无更明确的活跃工作；不能据此显示模型未提供的推理内容 |
| planning 规划步骤 | 从左至右看三个位置，最后回正 | 三个短台阶；3.2s | 显式计划工具/任务规划阶段；单个 todo 快照不足以证明正在规划 |
| searching 检索 | 先看左、停、看右、停；轻转头 ±3° | 小放大镜同步定位；2.8s | 搜索工具活跃；工具完成退出 |
| reading 阅读 | 左到右扫视并小幅换行；身体几乎不动 | 两条文档线；3s | 文件读取/矩阵读取；与网络检索区分 |
| working 执行 | 双眼略收、下视；一次小幅重心交换后停 | 两个交错短笔画；4.8s | 未分类的真实活跃工具；完成退出 |
| writing 编写 | 目光沿短行移动，笔停时抬眼；身体轻倾 2° | 小笔尖写两段后抬笔；2.6s | 写入/编辑或助手文本输出；子模式文案区分“编写文件”“整理回复” |
| verifying 核验 | 先缩眼聚焦，再双眼平齐 | 两条对齐线逐项标记；3.2s；循环标记不冒充结果通过 | 显式校验工具；工具结果另决定通过/存在问题 |
| coordinating 协同 | 眼神依次关注左右任务；主角色稳定 | 最多三个连接点轻传递；3.6s | 有活跃子调用且主调用主要在协调；显示真实活跃数量 |
| waiting 等待外部结果 | 放松双眼，朝任务方向短看后归中 | 静态时钟；6s 一次轻移眼 | 已知队列/外部依赖等待；不能仅因暂时无 token 触发 |
| awaiting-input 等待确认 | 眼睛张开注视用户，身体前倾 2°后保持 | 琥珀询问标记常驻；只入场一次 | interrupt.requested 或明确结构化确认；用户未回应一直保留；禁止自动继续 |
| blocked 需要处理 | 眼睛轻不对称，停止工作道具；一次回正 | 琥珀感叹号；进入 200ms 后静止 | 确定缺少资源/权限/关键依赖；配具体原因；可恢复问题优先此态 |
| reconnecting 连接恢复中 | 双眼中性，轻看连接点，禁止继续工作节奏 | 两端之间虚线呼应；3.6s | 仅真实重试/重连中；恢复成功播 recover，失败转 failed |
| delivering 整理交付 | 抬眼，身体从倾斜归正 | 文档滑入托盘；3s | 发布/装载结果/真实导出过程；checkpointed 单帧不能虚构长保存阶段 |
| completed 已完成 | 满意的上拱双眼；一次点头后安定 | 绿色对勾常驻 | 本轮成功且适用的产物装载完成；新任务退出；非保证标书业务合规 |
| partial 部分完成 | 一只柔和、一只保持关注；身体正立 | 琥珀半圆＋邻接说明 | 部分产物或页面缺失；必须有可核实的部分失败信号；禁止庆祝 |
| failed 执行失败 | 眼睛略低但清醒，一次小幅退让后稳定 | 红色叉号 | 终止且未恢复的错误；用户采取动作或新任务退出 |
| cancelled 已停止 | 工作动作减速、双眼归平，身体落定 | 中性方形停止标记 | 明确确认的取消事件；用户关闭面板不等于取消 |
| paused 已暂停 | 双眼半开，工作道具收起 | 中性暂停双线 | 后端确认暂停；不以浏览器隐藏推断；恢复信号退出 |
| sleeping 休息 | 两道闭合眼缝，身体轻倾 4°后静止 | 无 Z 字飘动 | 仅非工作展示/明确离线形象；运行、等待确认期间禁止睡着 |

## 7. 事件动作（8）与微表情（4）

事件动作叠加在基础态上。完成后回到**最新基础态**，不是触发前缓存的表情。以下时间为整句时长；样片选择事件会在播完后落定，点击“重播”再次播放。

| 标识 / 中文 | 动作句 | 时长 / 使用限制 |
|---|---|---|
| appear 出现 | 90% 体量展开 → 双眼打开 → 安定 | 480ms；仅新身份首次出现；视图重挂载不重播 |
| acknowledge 收到任务 | 看向输入 → 轻点头 → 进入工作 | 420ms；用户发送成功被接收时一次 |
| dispatch 派发任务 | 看向子任务方向 → 一个连接点移出 → 回正 | 560ms；按子调用 ID 去重，300ms 内多次派发合为一次 |
| receive-result 收到结果 | 目光迎向回来的点 → 小幅点头 | 480ms；非整轮完成；高频子结果合并 |
| milestone 阶段完成 | 抬眼 → 一个短亮点 → 恢复工作 | 520ms；重要阶段且有明确结果；每轮最多 3 次，间隔 ≥8s |
| notify 有新消息 | 眼睛略张 → 轻抬头 → 回落 | 600ms；只在明确提醒时；不重复催促 |
| recover 恢复连接 | 端点接合 → 双眼恢复聚焦 → 接当前工作 | 560ms；不显示成功对勾误导为任务完成 |
| celebrate 交付完成 | 100ms 预压 → 180ms 轻跃 → 260ms 落定 → 180ms 满意眼 | 720ms；仅真实且被见证的成功；大尺寸两枚亮点，日常标题栏无粒子 |

| 微表情 | 设计 | 触发 |
|---|---|---|
| blink 眨眼 | 合拢 → 短停 → 睁开 | 生理节奏/局部 hover；去重间隔 2s |
| glance 看一眼 | 双眼先动，身体最多跟随 1°，回正 | 主头像局部指针；不抢工作目标 |
| curious 好奇 | 一眼稍大，轻歪头 3°，恢复 | 待命时稀疏插入；输入到来立即结束 |
| content 会心 | 双眼短暂微弯，轻点头 | 用户明确正向反馈或非工作展示；不能用作结果正确性判断 |

现有 excited / surprised / suspicious / angry / drowsy / happy / confused / bored / proud / shy / sad / laughing / scared / playful 等不作为生产业务状态。少量积极表情归入微表情；愤怒、害怕、无聊不用于表达工作失败或等待。

## 8. 状态仲裁与切换

### 8.1 四条正交通道

1. `semantic`：持续工作状态，携带 runId、具体标签和可信参数。
2. `cue`：一个可打断的事件动作槽，包含 eventId / 归属 runId / 时间。
3. `attention`：视线目标与局部交互。
4. `presentation`：尺寸、身份、主题、动效偏好与可见性。

强弱顺序：**当前轮终态 / 确定故障 → 人工介入 / 明确受阻 → 当前真实工作 → 用户局部回应 → 待命微表情**。同类事件以当前 runId 和已验证时间顺序更新；旧轮 late event 不覆盖新轮。终态不等于所有错误都失败：有保留产物且证据支持时转 partial。

### 8.2 调度规则

| 场景 | 规则 |
|---|---|
| 同状态的新 token / 参数变化 | 保持动作相位，只更新标签/实际进度；不重建引擎 |
| 普通工作子状态变化 | 候选稳定 180ms 后切换；当前表现至少 600ms；短促来回合为较粗工作态 |
| 确认、故障、停止到来 | 下一个渲染帧更新文字与语义标记；姿态 120–200ms 收束；绕过 600ms 驻留 |
| 切换中反向 | 从当前显示位置与速度转向；不先回 idle；眼形从当前插值形状继续 |
| 多个活跃工具 | 维护按 callId 归属的活跃集合；当前主操作优先；无法区分时 working；不能用最新 completed 掩盖更早 started 且仍活跃的工具 |
| 主从并行 | 主角色用主流活动，主流在等待子任务时 coordinating；子角色按 children 派生；不用子 token 改主脸 |
| 眨眼遇到新状态 | 合并到当前闭合过程，最多保留一次待播；确认/故障时先确保语义标记立即出现 |
| 一次性动作被插播 | 仅一个槽；高优先级取代，低优先级丢弃；不排长队 |
| 完成后立即新任务 | 完成动作立即让位；历史完成标签可留在历史记录，主角色进入新任务 |
| 历史恢复 / 页面刷新 | 显示当前静态语义；不庆祝、不出现、不补播离线期间事件 |
| 页签隐藏/角色离屏 | 停逐帧绘制，继续收真实业务状态；恢复时对齐最新状态，不补跑时间 |
| 长时间无消息 | 不自行从 thinking 变 failed / paused；可在状态文字说明距上次更新时长，不能虚构队列或重试 |

### 8.3 关键动作分镜

- 收到任务：0ms 视线定位 → 60ms 轻前倾 → 140ms 点头 → 300ms 开始归正 → 420ms 工作态。
- 阅读转编写：当前眼神结束这一段 → 120ms 目光移至下方 → 200ms 笔尖进入 → 320ms 新节奏开始；最多延迟 180ms，不等待读完一圈。
- 工作转确认：0ms 标签改为“需要你确认” → 80ms 停笔/收道具 → 160ms 注视用户 → 200ms 标记与姿态稳定；不持续晃动催促。
- 子任务回收：0ms 主眼看向子任务 → 120ms 点回到主角色 → 280ms 点头 → 480ms 恢复协调或下一项工作。
- 完成交付：0ms 收笔 → 100ms 预压 → 280ms 到达跳跃顶点 → 540ms 落定 → 720ms 完成眼形与对勾保留；若尺寸 <48px，以点头替代跳跃。
- 错误到恢复：错误态静止 → 用户实际重试后 reconnecting → 收到恢复证据后 560ms recover → 最新工作态；点击按钮本身不能表示已恢复。

## 9. hagent 契约映射与能力边界

查阅 `hagent/docs/sse-message-events.md`，并对照当前 `workspace.ts`、`timeline.ts`、`toolLabel.ts`、`server/routers/messages.py`。事件手册的 sandbox 接入描述存在前后不一致，故本方案不默认依赖某个 sandbox 事件必达；接入时按运行中的真实事件链验证。

| 信号 | 可派生状态 | 当前接入级别 / 注意 |
|---|---|---|
| phase=creating / uploading | connecting / uploading | 现有可用；创建项目不等于出生一个新角色 |
| ingest.progress | parsing + done/total 页数 | 后端契约已有；主产品 Bot 尚未消费，需要增加轻量状态投影 |
| ingest.completed.failed_pages | 保留原文缺页注意信息；本轮结束后可 partial | 不能收到解析完成就宣告整个标书完成 |
| ingest.failed | 解析阶段注意/受阻；随后 Agent 若继续则恢复真实工作态，保留警示 | 契约明确不阻断消息；不得自动映射终态 failed |
| message.delta.thinking | thinking | 从标准字段取，不能通过助手句子猜情绪 |
| message.delta.content | writing / 子模式“整理回复” | 文本输出不是语音播报，不显示音频波形 |
| tool_call.started / completed | 对应工作态 / 转回其他仍活跃的调用 | started 带参数分片，同 callId 不算重复开始；completion 不自动视作业务通过 |
| Read / 文件读取类 / prose_get_matrix | reading | 工具名显式白名单；本项目工具集合接入时重新确认 |
| Glob / Grep / WebSearch / 查询定位类 | searching | 搜索与文件读取区分，未知名称回退 working |
| Write / Edit / prose_submit_matrix_records / 更新条目类 | writing | 写入成功不等于发布成功 |
| prose_validate_matrix | verifying | 校验过程；结果存在问题转相关注意信息，不能显示完成对勾 |
| prose_publish_matrix / loading_results | delivering | 必须确认发布成功/矩阵加载完成才能 completed |
| Agent 活跃调用 + parent_tool_use_id | coordinating；子节点各自工作 | 主流和子流分开处理；同轮多子调用聚合 |
| todo.updated | 真实任务数量 / 依赖信息 | 快照不能单独证明整个 Bot 被阻塞或正在规划；有可执行任务时继续执行 |
| interrupt.requested | awaiting-input | 后端有信号，主前端尚未投影；当前 interrupt 恢复接口是占位，样片确认流程只演示设计 |
| workspace.checkpointed | 已保存证据 / 可选 milestone | 是完成后的事实，不用于制造长时间“保存中”；checkpoint 之后仍可能 error |
| done | completed / partial / 保持已确认的受阻语义 | done 只代表流正常结束；hook.blocked 后也有 done，不能当作成功成果 |
| error + recovery 信息 | failed / blocked / partial | 资源不足等需要可操作说明；自动重试不存在时不可播 reconnecting |
| 传输中断 | 状态未知，保留最近工作态但停止假工作节奏并显示连接说明 | 需要显式 transport 投影；不等于取消/后台暂停 |
| 已确认取消 / 暂停 / 重连 | cancelled / paused / reconnecting | 预留表现；当前 RunPhase 没有这些值，须以后端或传输控制真实能力为前提 |

planning、listening、sleeping 是有条件的产品表现态；无对应输入或生命周期时不自动启用。分片高频流仍走现有 rAF 合帧，不在每个 token 中启动动画，不对任意工具结果正文做情绪分类。

## 10. 无障碍与性能

- 静态语义始终可读。≥32px 用可辨别标记，所有尺寸配邻接中文状态；颜色不单独承载意义。20px 的细分工作态允许共享姿态。
- `prefers-reduced-motion` 动态切换立即生效：停止循环、跳跃、眼神跟随和轨迹；只更新静态眼形与标记，必要时 ≤120ms 透明度变化。用户主动“暂停预览”冻结当前帧；减少动效展示代表姿态，两者不同。
- 可交互头像使用现有真实按钮，键盘焦点沿用产品焦点环；焦点可触发温和注视；触屏没有模拟 hover。点击仍执行原有展开/收起功能，不能新增无语义逗弄操作。
- 有邻接状态文字的 SVG `aria-hidden=true`；独立头像使用中文 accessible name。播报放在一个业务状态区域，避免主头像、看板、标题重复播报。只有阻断性新错误使用 alert。
- 同屏一个完整运动主角色，子角色默认低振幅/静态。可见子头像较多时只让当前关注的一项与最多两项短事件运动；大批量完成汇总为一次。
- 一个共享时钟可调度可见实例；终态、静态、离屏实例不维持独立 rAF。停止时清理 onceTimer、眨眼队列、指针监听、观察器与样片计时器。
- 形体位移/旋转/缩放使用 transform；辅助淡入用 opacity；双眼路径 morph 限制节点数量。无逐帧布局写入，指针 rect 按布局变化缓存。眼形 SVG 重绘成本需实测，不声称全靠合成层。
- 目标（待产品实现验收）：一个主角色 + 12 个静态子角色，无角色引起的 >50ms 长任务；动画更新自身的主线程开销 P95 <2ms/帧，在指定测试机器/浏览器记录。静止/离屏无持续帧任务。样片不是性能基准。

## 11. 接入计划（确认后执行）

1. **资产与表达层**：母版、自绘双眼、道具/标记、24 态关键姿态；经 `components/ui/icons/index.tsx` 统一导出身份资产，保留 ProseBot React 壳。
2. **动作编排**：持续态与事件槽分开；同状态幂等、从当前值衔接、尺寸降级、可见性与 reduceMotion；复用已有 SVG 引擎合理部分，不引入 Skia/新动效依赖。
3. **业务投影**：独立小模块聚合活跃 callId、父子关系、可信进度与人工介入；不破坏 workspace rAF 批处理；状态文字与头像共用投影。
4. **主角色落地**：先接 MessageWindow，统一其头像光圈与角色节奏；修复挂载/销毁/完成去重；移除旧 39 态里不适合生产的自动随机特技。
5. **按能力启用扩展状态**：缺少数据时使用清晰回退；补齐审批恢复、暂停、取消等后端能力属于另行确认的功能工作，不隐含在图标视觉接入里。
6. **可选子角色**：确认看板信息密度后再接角色家族，现有状态图标可继续作为紧凑方案。

旧枚举兼容：dictating→writing/整理回复；orbit→coordinating；loading→delivering（必须按原调用语义区分）；alerting→blocked 或 failed；spawning→appear 事件，创建会话→connecting；celebrate→事件；receiving→receive-result；sending→dispatch 或 delivering；progress/radar 是辅助表现，不暴露为业务态；dragging/bouncing/powering-down 仅在对应真实交互出现时另行设计，当前角色不是可拖拽物，不默认保留这些业务入口。

## 12. 验收清单与本轮边界

设计样片包含：36 个可选择条目、24 态关键姿态总览、8 个可重播事件、4 个微表情、实际尺寸对照、主题切换、减少动效、暂停、正常/人工确认/恢复/部分完成四条情境、快速切换与优先打断演示、主从身份样本。

样片是独立的设计播放器，不连接 SSE，不复用产品引擎；确定性序列用于比较动作。随机眨眼调度、真实事件仲裁、视图重挂载去重、共享帧调度与全部后端映射是实现阶段验收项。播放中的示例百分比只代表演示数据。

产品实现质量门：`pnpm typecheck` + `pnpm lint`。重点人工检查：20/24/32/48/64/128px；浅/深主题；连续 switching A→B→A；完成被新任务打断；重复 callId；跨轮 late event；10+ 子任务并发；人工确认后 done；缺页后任务继续；断流后无自动恢复；页面隐藏/恢复；动态减少动效；卸载后无回调；键盘与触屏。性能目标需实测报告，不凭动画 API 判定。
