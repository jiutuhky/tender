# PDF 溯源预览：招标文件原件对照与版面高亮

> 决策来源：2026-08-04 grilling 会话。承接 `.scratch/source-trace-preview/PRD.md`（溯源预览的形态与交互事实来源），本文只改**载体与锚点管线**，不推翻其交互决策。
> 领域术语沿用 `frontend/CONTEXT.md`「溯源预览」小节：溯源预览（预览层）、来源签、活跃 ref、高亮选区、文档注册表。本文新增：**原件**（上传的 PDF）、**预览版**（重压缩后下发浏览器的 PDF）、**版面块**（OCR 输出的 layout block）、**sidecar**（md 行号 ↔ 版面块 ↔ 页面矩形的映射文件）。

## Problem Statement

标书核验人员逐条核对应答矩阵的提取结果时，预览层给他看的是 **MinerU/OCR 转出来的 Markdown**——而条目本身就是 LLM 从这份 Markdown 里抽出来的。**拿抽取的输入去核验抽取的输出，是循环论证**：OCR 把字识错、把表切碎、把引号读成上标（既有 PRD 已承认全语料 69 张表破 17 张、52 行标记泄漏到正文），对照 Markdown 一辈子看不出来。核验链路上有两层可能出错——OCR（PDF→md）与 LLM（md→条目）——而当前预览层只能验第二层。

同时，产品最终形态是用户上传 PDF、由平台走 `PDF → OCR → MD`；现在前端只收 `.md`（`accept=".md,text/markdown"`）是开发期抄的近路。原件从未进过系统，也就没有任何东西能作为核验基准。

## Solution

预览层的载体从「渲染态 Markdown」换成 **招标文件原件本身**，高亮从「md 块级染色」换成 **画在页面上的版面矩形**。

上传口改收 PDF。后端把 OCR 作为**上传后的确定性前置任务**：分批调用已部署的 PaddleOCR-VL 服务，从版面块拼出 md 的同一次操作里，顺带产出 **sidecar**——md 行号 → 版面块 → (页码, 归一化矩形) 的映射。抽取契约完全不动：LLM 照旧读干净的 md、照旧吐 `line_span`。

点来源签，预览层用 EmbedPDF 打开该文档的预览版，滚到命中矩形所在页并居中，把矩形高亮出来。核验人员看到的是**原件那张纸**，OCR 讹误当场现形。既有交互——盖满画布的浮层、对照条内嵌人工动作、多来源步进器、Esc 逐层退、reduced-motion 即时切换——原样保留。没有 PDF 的文档（历史项目、开发期 `.md` 语料）降级到现有 md 预览，不是坏掉。

## User Stories

1. 作为标书核验人员，我想在预览层看到招标文件**原件**而不是 OCR 转出的文本，以便同时核验 OCR 与 LLM 两层是否出错。
2. 作为标书核验人员，我想让高亮画在原件页面的对应位置上，以便一眼确认提取内容在原文里的确切落点。
3. 作为标书核验人员，当 OCR 把某个字、某个数值识错时，我想通过对照原件当场发现，以便及时纠正而不是把错误带进投标文件。
4. 作为标书核验人员，当 OCR 把一张表切碎或读串行时，我想看到原件上那张表的真实样子，以便判断提取出的评分规则是否可信。
5. 作为标书核验人员，我想直接上传 PDF 招标文件，以便不必自己先去外部工具转 Markdown。
6. 作为标书核验人员，我想在上传后看到「原文解析 N/M 页」的进度，以便知道系统在干什么、还要等多久。
7. 作为标书核验人员，当某几页 OCR 失败时，我想其余页照常可用、失败页明确标出，以便一份几百页的文件不因个别页作废。
8. 作为标书核验人员，我想让来源签的点击行为与现在完全一致（点开、点亮、单活跃），以便不必重新学习交互。
9. 作为标书核验人员，我想在预览层内用来源步进器逐条走完同一条目的全部来源，即使它们落在不同页甚至不同文档。
10. 作为标书核验人员，当一条来源跨页（原文段落被分页切开）时，我想两页上的矩形都被高亮，以便理解这条提取横跨了页边界。
11. 作为标书核验人员，我想在预览层里自由翻页阅读上下文，以便理解条款所在章节的完整语境。
12. 作为标书核验人员，我想看到当前页码与总页数，以便知道自己在文档的什么位置。
13. 作为标书核验人员，我想能放大页面看清小字与印章，以便核验密集表格与盖章页。
14. 作为标书核验人员，我想对照着原件直接点「确认」或标注「合规/正偏离/负偏离」，以便核验与落状态在同一视野内完成。
15. 作为标书核验人员，我想用 Esc 逐层退出（先退预览层、再关抽屉），以便只退出阅读层而不丢失条目浏览位置。
16. 作为标书核验人员，当文档没有 PDF 原件（历史项目）时，我想溯源降级到现有的 md 预览而不是直接失效，以便老项目仍可核验。
17. 作为标书核验人员，当 sidecar 缺失或与 md 不匹配时，我想文档照常打开、顶部黄条说明「原文映射失效」，以便知道该条来源需人工翻找而不是功能坏了。
18. 作为标书核验人员，当来源命中的块落在页眉页脚这类被忽略的版面元素上、拿不到矩形时，我想文档照常打开并看到「未能定位」提示。
19. 作为标书核验人员，当预览版取不到时，我想看到面板内错误态与重试入口，以便网络抖动后不用重开抽屉。
20. 作为标书核验人员，当来源指向的文档不在注册表里时，我想看到置灰不可点的签与悬停说明，以便立刻明白溯源缺失。
21. 作为标书核验人员，我想在文档加载期间看到载入占位，以便确知系统正在取原件。
22. 作为标书核验人员，我想能下载原件，以便离线归档或转发给同事。
23. 作为标书核验人员，当上传的文件超出页数或体积上限时，我想立刻收到明确报错，以便不必等一个注定失败的漫长解析。
24. 作为标书核验人员，我想让预览层的打开与退出动效与现在一致（浮层淡入 + 轻缩放，进出镜像），以便空间关系稳定可预期。
25. 作为开启了减弱动态的用户，我想所有过渡与滚动定位都变为即时切换，以便不被动效晃到。
26. 作为键盘用户，我想 Tab 聚焦来源签、Enter 触发溯源，焦点循环仍锁在浮层内。
27. 作为标书核验人员，我想重复打开同一文档时内容即时呈现，以便逐条核验不被网络等待打断。
28. 作为标书核验人员，我想相信高亮指的位置一定是对的——**宁可显示「未能定位」，也不要稳稳地指到错误的地方**。
29. 作为前端开发者，我想预览版与 sidecar 都经同源代理获取，以便 API key 继续只在服务端持有。
30. 作为后端维护者，我想 OCR 是确定性前置任务而非 agent 工具调用，以便失败、重试、断点续跑的语义清晰可控。
31. 作为后端维护者，我想 OCR 产出的 md 与 sidecar 不可被 agent 改写，以便溯源锚点永远成立。
32. 作为后端维护者，我想原件等大二进制不进 project 的 git 仓，以便仓体积与 checkpoint 性能不被拖垮。
33. 作为后端维护者，我想「版面块 → md + sidecar」的装配逻辑收在可独立测试的纯模块里，以便行号记账这类易错逻辑有回归保护。
34. 作为产品维护者，我想 EmbedPDF 的 WASM 首屏体积在动工早期就被实测，以便不可接受时还来得及换方案。

## Implementation Decisions

### OCR 与锚点管线

- **OCR 路线已定**：PaddleOCR-VL（`paddleocr-vl-1.6-hps`），HPS Gateway 已部署，端点 `/layout-parsing`（POST）与 `/restructure-pages`。服务地址走配置，不硬编码。
- **OCR 是上传后的确定性前置异步任务**，不是 agent 工具。理由：确定性 ETL 不该由 LLM 决定何时跑、跑几次；失败/重试/断点续跑语义需要干净。md 与 sidecar 就绪后才起 agent。
- **抽取契约不动**：`line_span` 维持既有语义（1-based 闭区间，指向 OCR 规范化 Markdown 的源文件行号）。LLM 照旧读不带任何标记的 md。否决了「改用 block_id 当锚点」——要改抽取 prompt、改 matrix 契约、已有数据失效，且标记入 prompt 会引入 LLM 编造/漏标的新出错面。
- **sidecar 由构造产生，禁止事后模糊对齐**。拼装 md 与产出 sidecar 必须是同一段代码的同一次输出：遍历版面块时一边追加 md 文本一边记账行号。任何「先拼 md、再回头把块文本匹配回去」的做法一律不接受——模糊匹配正是本方案要绕开的东西。

**实测确立的事实（`reference/ocr-response-sample.json` 为一页真实响应）：**

- 每个版面块返回 `block_label / block_content / block_bbox / block_polygon_points / block_id / block_order / group_id`。
- `markdown.text` 就是 `parsing_res_list` 按序拼出来的：`doc_title` → `#`、`paragraph_title` → `###`、table 的 HTML 逐字照抄。
- **版面块与 md 段一一对应**：每块在 md 里正好占一个由空行分隔的段落，块内容本身不含换行（长表格即一行超长 HTML，与既有语料一致）。因此映射粒度与现有块级高亮**完全一致，无精度退步**。
- 坐标是**渲染图像的像素空间**：A4（595×842pt）返回 `width:1190, height:1684`，即 2× / 144 DPI；`dataInfo.pages[i]` 逐页给出图像尺寸。
- `use_doc_preprocessor: false`——已避开 PaddleOCR-VL 已知的 unwarping 导致 bbox 与原件错位的坑。**该参数不得改为 true。**
- `markdown_ignore_labels` 会把 header / footer / number / footnote 等排除出 md：**版面块数量多于 md 段**，这些块没有对应行号，落 sidecar 时不产出条目。
- `/restructure-pages` 做跨页合并：**一个 md 段可能对应多页上的多个矩形**，sidecar 的矩形字段必须是数组。
- 吞吐实测约 **1.07 s/页**（10 页密集页 10.7s）。按语料估算（6–7.7 万字符 ≈ 100 页量级），一份招标文件约 3–10 分钟——**必须异步、必须分批**（请求体是 base64 JSON，整份塞入体积不可接受）。

**sidecar 契约（schema v1）**——与 md 同目录、进 git（文本可 diff 可审阅）：

```jsonc
{
  "schema": 1,
  "mdSha256": "…",                                     // 保险丝：不匹配即判映射失效
  "pages": [{ "index": 0, "width": 1190, "height": 1684 }],
  "blocks": [{
    "mdStart": 12, "mdEnd": 12, "label": "table",
    "rects": [{ "page": 3, "bbox": [0.118, 0.207, 0.532, 0.280] }]
  }]
}
```

`bbox` 归一化到 0–1（除以该页 `width`/`height`），与页面绝对尺寸解耦；`rects` 为数组以容纳跨页合并块；`mdSha256` 即便在 md 只读的前提下也保留，防手工改动与迁移事故。

### 存储与不可变性

- **原件与预览版按 sha256 内容寻址，存到 project workspace 之外的 blob 目录，不进 git**。`documents` 表已有 `sha256` 列，天然是寻址键。理由：原件是不可变输入，不需要版本化；而工作区的策略是「全量回写 + 排除名单」，agent 每跑一轮就可能把几百 MB 二进制再提交一次，仓会在几轮内爆掉（该 workspace 设计文档自己已预警过大量文件对 `git status/diff` 的开销）。
- **仓内只留 md 与 sidecar 这类可 diff 可审阅的文本。**
- **OCR 产出的 md 与 sidecar 对 agent 只读**：自研文件工具对其写入直接拒绝并返回可读错误（复用工作区设计 W8 的路径锁抓手）。agent 要修正 OCR 讹误就另写到 `structured/` 或 `deliverables/`，不动原文。否决了「可改 + sha256 失效兵兵」（改一个字废掉整份文档的溯源）与「可改 + 重建映射」（重建就得做模糊对齐）。
- **预览版压缩的硬约束：页数与逐页页面尺寸必须与原件一致**，否则归一化 bbox 全部错位。dpi 档位靠一份真件实测敲定（起点建议 150dpi 重编码图片流）。原件保留并提供下载入口。

### 渲染与前端

- **载体用 EmbedPDF**（MIT，PDFium WASM，内置虚拟化）。否决了 `@react-pdf-viewer`（商用需购授权）与 `react-pdf-kit`（付费）；否决了内嵌 pdf.js 官方 viewer（跨 iframe 通信 + 样式无法融入 Frost + 对照条与步进器难做）。
- **已知约束并已接受**：PDFium WASM **无法做 Range 分块加载**（`FPDF_LoadCustomDocument` 要求同步回调，需等 WASM JSPI），整份预览版必须下载并驻留 WASM 堆。这正是「服务端出压缩预览版」这条决策的由来。曾评估的备选是「OCR 顺带产出页位图、前端虚拟滚动图片列表」（坐标 1:1 零变换、按页懒加载、无 WASM），**明确否决，保留为 WASM 体积不可接受时的回退方案**。
- **高亮走 annotation 能力**：`createAnnotation(pageIndex, annotation)` 程序化建矩形，`autoCommit: false` 保证纯内存不写进 PDF，`readOnly` 使其「渲染但完全惰性」（不可选中、无手柄、无菜单）。若 `readOnly` 的视觉不可控，退回照 Layout Analysis 插件的 `<LayoutAnalysisLayer />` 形状自写一层覆盖层。
- **预览层只管「看」**：不做文本层，Selection 插件不装。理由：真实招标文件电子版与扫描件混杂不可控，扫描件本无文本层；而 OCR 只有块级（段落级）bbox，铺出来的透明文本层选区会与视觉明显错位，要做对得拿行/词级坐标。定位职责完全交给溯源高亮。
- **定位**：滚到首个命中矩形所在页并居中，多矩形（含跨页）全部高亮，来源步进器在矩形间跳。
- **既有交互全部保留**：盖满画布的浮层、对照条内嵌 `ItemActions`、来源步进器、Esc 逐层退、全局单活跃 ref、gsap 只动 transform 与 opacity、Frost 时长档位、`prefers-reduced-motion` 下全部退化为即时切换。新增页码指示与缩放档位。
- **状态归属不变**：活跃 ref、层开合、载入态留在抽屉层 context，不进全局 workspace store（SSE 事件批处理是 store 的性能关键路径）。文档注册表与内容缓存仍在数据层。
- **md 预览作为降级路径保留**：现有 unified 管线（rehype-raw + KaTeX + 纸面排版）与块级高亮原样留用，服务于无 PDF 的历史文档与开发期 `.md` 语料。预览层的壳与载体解耦，两种载体可替换。

### 容错分层

沿用「坏数据必须可见、不静默吞掉」的一贯立场。**宁可显示「未能定位」，也不要稳稳地指到错误的地方。** 五类互不串扰：

| 情形 | 表现 |
| --- | --- |
| 文档不在注册表 | 签置灰不可点 + 悬停说明（现状不变） |
| 文档无 PDF 原件 | 签可点，走 md 降级预览 + 块级高亮 |
| sidecar 缺失，或 `mdSha256` 与 md 不匹配 | 照常打开 PDF，顶部黄条「原文映射失效」，不滚动不高亮 |
| `line_span` 越界，或命中块无 `rects`（落在被忽略的页眉页脚等） | 照常打开 PDF 停在第 1 页，黄条「未能定位」 |
| 预览版取不到 | 面板内错误态 + 重试（现状不变） |

### 契约面

- 新增两条读端点（预览版字节流、sidecar JSON），鉴权、404、分页语义与既有矩阵读端点同构。
- 前端新增对应的两条同源读代理，API key 继续只在服务端持有。
- 上传口从 `.md` 改收 PDF；页数与体积设硬上限，超限**明确报错而非慢死**。
- 解析进度经既有 SSE 通道上报「原文解析 N/M 页」，不新开通道。SSE 消息契约本身不受影响——本特性只新增 REST 读路径与一段前置任务，不碰消息解析与渲染。

## Testing Decisions

好测试只测外部行为，不测实现细节。缝越少越好，理想是一条。

- **唯一新增缝：装配器。** `OCR 响应 → (md, sidecar)` 做成纯函数，不碰网络不碰磁盘。喂真实响应样本，断言产出的 md 文本与 sidecar 结构。这一条缝盖住全部易错逻辑：块→md 拼装规则、行号记账、被忽略标签的块不占行号、跨页合并块产出多 rects、bbox 按各页尺寸归一化、`mdSha256` 计算。**OCR 服务不 mock**——它在缝外，响应样本进仓当夹具（`reference/ocr-response-sample.json` 为起点，实现期补一份多页样本）。
- **复用既有后端缝**：两条读端点的用例落在既有 REST adapter 的 TestClient 测试文件，断言响应形状、分页语义、404 与鉴权行为，不 mock 服务内部。prior art 是矩阵 overview/items 端点的既有用例风格。
- **复用既有前端口径**：不引入测试框架（延续既有收口决策）。质量门维持 `pnpm typecheck`（strict + `noUncheckedIndexedAccess`）+ `pnpm lint`。`line_span → rects` 的判定与容错分层判定收进 `lib/trace/` 纯模块，组件只消费，保持未来可测性。
- **刻意不设缝**：OCR 分批调度与断点续跑（IO 编排）、EmbedPDF 渲染与高亮（第三方 + DOM）、预览版压缩（靠实跑比对页数与逐页尺寸不变）。这三处靠实跑验收。
- **验收走实跑**：起 hagent + 前端，上传真实招标文件 PDF 跑完解析，驱动「点签 → 开层 → 翻页定位 → 矩形高亮 → 多来源跨页步进 → 五类容错态 → md 降级 → reduced-motion」全路径。

## Out of Scope

- 预览层内的文本选中、复制、全文搜索（预览层只管「看」）。
