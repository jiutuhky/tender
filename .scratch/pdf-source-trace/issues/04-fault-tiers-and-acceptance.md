# 04 容错分层、降级与实跑收口

## Parent

`.scratch/pdf-source-trace/PRD.md`

## What to build

把坏数据全部变成可见且互不串扰的状态，把降级路径接上，然后拿真招标文件跑完全路径。

贯穿原则：**宁可显示「未能定位」，也不要稳稳地指到错误的地方。** 高亮指错位置比不高亮危险得多——核验人员会信它。

五类容错：文档不在注册表 → 签置灰不可点 + 悬停说明；文档无 PDF 原件（历史项目、开发期 `.md` 语料）→ 签可点，降级到 md 预览与块级高亮；sidecar 缺失或 `mdSha256` 与 md 不匹配 → 照常打开 PDF，顶部黄条「原文映射失效」，不滚动不高亮；`line_span` 越界或命中块无 `rects`（落在被忽略的页眉页脚等）→ 照常打开 PDF 停在第 1 页，黄条「未能定位」；预览版取不到 → 面板内错误态 + 重试。

收口项：页码指示（第 N / M 页）与缩放档位；原件下载入口；`prefers-reduced-motion` 下全路径动效与滚动定位退化为即时切换；焦点循环锁在浮层内、Tab 聚焦签 Enter 触发。

## Acceptance criteria

- [ ] 五类容错各自可复现、表现符合上述口径，且互不串扰（构造坏数据逐类验证）
- [ ] 无 PDF 的文档降级到 md 预览，块级高亮照常工作，不是失效态
- [ ] 页码指示与缩放档位可用
- [ ] 原件下载入口可用，下载到的是原件而非预览版
- [ ] reduced-motion 下浮层进出、滚动定位、高亮出现全部为即时切换
- [ ] Tab 聚焦来源签、Enter 触发溯源，焦点循环锁在浮层内；Esc 逐层退（先退层、再关抽屉）
- [ ] 关抽屉后溯源状态整体重置，再次打开是干净初始态
- [ ] 实跑验收：起 hagent + 前端，上传真实招标文件 PDF 跑完解析，驱动「点签 → 开层 → 翻页定位 → 矩形高亮 → 多来源跨页步进 → 五类容错 → md 降级 → reduced-motion」全路径
- [ ] `pnpm typecheck` + `pnpm lint` 通过，hagent pytest 全绿
