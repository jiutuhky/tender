# 统一沙箱容量准入与可重试恢复

## 现场

三个新项目发送消息均返回 503：sandbox pool exhausted (max=4)。四个旧项目
虽已暂停，仍计入池容量，默认要等 30 分钟才存盘释放。句柄保持 16，属于独立故障。

## 处理范围

- warm、新建、快照恢复共用有界准入；数量满额和内存/CPU 额度不足都进入回收。
- 压力回收按最近使用时间选择没有活跃 Run 的项目，保存快照后释放资源；
  不等待候选项目锁，避免持锁请求之间互等；失败保留环境。
- 等待期间重新检查名额，支持默认 release 销毁模式；工厂异常释放占位。
- 快照恢复仅容量不足时保留快照，容量恢复后原会话可再次恢复。
- 503 提供错误码、原因和 Retry-After；同源代理保留 JSON 类型和重试头；
  前端明确资源不足及重试方式，兼容旧错误体，不自动重放有副作用的消息。

## 验收

单元与接口：第五项目、并发竞争、活跃保护、快照失败、锁竞争、宿主额度、
释放后等待者准入、工厂失败回滚、恢复重试、错误契约。
真实虚拟机：四个项目后启动第五个，回到第一个项目核对原文件。
前端 typecheck、lint、代理与客户端错误行为；重启后日志和服务检查。

## 实测与限制

真实第五项目回归首次揭示 SDK 的 DISK 快照沿用原 IP，IP 被新环境复用时会
恢复失败。按照项目工作区架构，快照是可丢弃缓存；集成测试已接入正式
WorkspaceCheckpointer 和 WorkspaceMaterializer，验证即使走冷启动回退，
已完成任务的 deliverables 文件仍完整还原。未更改或升级锁定的 SDK。

未承诺保留快照失败后的临时环境或未提交文件；正式成果以项目工作区及资产库为准。
本次未发送真实模型生成请求；资源准入使用真实虚拟机验证，接口使用模拟模型隔离验证。
