# 溯源预览：应答矩阵条目的招标文件原文对照

> 决策来源：2026-07-16 grilling 会话（形态线框对比 artifact：https://claude.ai/code/artifact/cd09d501-1e50-4849-9ca8-5e0658278aff ）。
> 领域术语见 `frontend/CONTEXT.md`「溯源预览」小节：溯源预览（原文面板）、来源签、活跃 ref、高亮选区、文档注册表。

## Problem Statement

标书编制人员在抽屉详情里逐条核验商务/技术应答矩阵与评分办法的提取结果（确认、标注合规/偏离），但条目上的来源只是「来源 L120-124 · 技术需求」一行灰字——要核对原文，只能自己打开招标文件手动翻到对应行。提取由 LLM 完成、明确要求人工核验，可产品没有给核验动作提供原文对照，逐条核验实际做不下去。

## Solution

来源行升级为可点击的**来源签**。点击任一来源签，抽屉加宽为**对照双栏**：左栏滑出**原文面板**，以渲染态 Markdown 呈现招标文件（标题层级、表格成型、衬线正文），滚动定位到对应行区并整块高亮；右栏条目列表原样保留，人工动作（确认/应答状态标注）同屏可用。面板打开后常驻，点其他来源签只切换定位与高亮（全局单活跃 ref）；窄屏降级为抽屉内二级视图。数据坏掉时分层容错：注册表缺失置灰签、文件读取失败面板错误态、行号越界照开文档黄条提示。

## User Stories

1. 作为标书核验人员，我想点击商务条目的来源签直接看到招标文件对应原文并高亮，以便不离开条目列表就核验提取是否忠实原文。
2. 作为标书核验人员，我想在技术条目上获得同样的溯源能力，以便对 ★ 实质性条款逐条对照原文。
3. 作为标书核验人员，我想在评分办法表格的「来源」列点击溯源，以便核对每个评分项的分值与规则是否照抄无误。
4. 作为标书核验人员，我想在否决项红区（带合法来源的条目）也能点开原文，以便对废标级条款做最严格的核对。
5. 作为标书核验人员，我想对照着原文直接点「确认」或标注「合规/正偏离/负偏离」，以便核验和落状态在同一个视野里完成。
6. 作为标书核验人员，当一个条目有多条来源时，我想逐一点跳每条来源签，以便看全该条目在全文中的每个落点。
7. 作为标书核验人员，当来源跨文档时，我想点签后面板自动切到对应文档，以便无感知地跨文档核验。
8. 作为标书核验人员，我想让当前活跃的来源签点亮、其余保持常态，以便始终知道面板正在展示哪条来源。
9. 作为标书核验人员，我想让高亮选区随定位滚动进入视野中部，以便一眼落在要核对的内容上。
10. 作为标书核验人员，当来源命中单行大表格时，我想看到整张表格被高亮，以便理解「这条提取来自这张表」。
11. 作为标书核验人员，我想在原文面板里自由上下滚动阅读上下文，以便理解条款所在章节的完整语境。
12. 作为标书核验人员，我想让面板打开后常驻，切换条目、切换过滤签时不收起，以便连续逐条核验。
13. 作为标书核验人员，我想手动关闭原文面板让抽屉回到原宽，以便核验完回到纯列表浏览。
14. 作为标书核验人员，关闭抽屉时我希望溯源状态整体重置，以便下次打开是干净的初始态。
15. 作为标书核验人员，当行号越界或缺失时，我想文档照常打开并看到「未能定位」的黄条提示，以便知道该条来源需要人工翻找而不是功能坏了。
16. 作为标书核验人员，当来源指向的文档不在注册表里时，我想看到置灰不可点的签和悬停说明，以便立刻明白溯源缺失而不是白点一次。
17. 作为标书核验人员，当文件读取失败时，我想在面板内看到错误态和重试入口，以便网络抖动后不用重开抽屉。
18. 作为标书核验人员，我想在文档加载期间看到面板内的载入占位，以便确知系统正在取原文。
19. 作为标书核验人员，我想让原文以渲染态呈现（标题、列表、表格成型，衬线正文），以便像读公文一样读招标文件，而不是啃原始 Markdown。
20. 作为窄屏用户，我想在放不下双栏时得到抽屉内二级视图（带「返回条目」），以便小窗口下仍能完成溯源。
21. 作为键盘用户，我想用 Tab 聚焦来源签、Enter 触发溯源，且焦点循环仍锁在抽屉内，以便无鼠标完成核验。
22. 作为开启了减弱动态的用户，我想所有过渡（加宽、滑入、滚动定位、高亮出现）都变为即时切换，以便不被动效晃到。
23. 作为标书核验人员，我想重复打开同一文档时内容即时呈现（缓存命中），以便逐条核验不被网络等待打断。
24. 作为标书核验人员，我想双栏打开时既有的过滤签与分类锚点照常工作，以便在对照状态下继续按「★ 实质性 / 高风险」聚焦。
25. 作为标书核验人员，我想抽屉加宽的过程可以被打断（动画中点其他签不锁输入），以便操作节奏不被动效绑架。
26. 作为标书核验人员，我想面板从左缘滑入、原路退出且缓动镜像，以便空间关系稳定可预期。
27. 作为标书核验人员，我想高亮用系统蓝的浅染而非橙红，以便不与「实质性/高风险」的警示色语义打架。
28. 作为前端开发者，我想 document_id→路径映射与文件内容都经同源代理获取，以便 API key 继续只在服务端持有。
29. 作为后端维护者，我想 documents 读端点与既有 REST 面同构（鉴权、分页、错误语义一致），以便契约面保持可预期。
30. 作为产品维护者，我想溯源纯逻辑（签可用性判定、行号→块映射、容错分层）收在可独立类型检查的纯模块里，以便未来引入测试框架时可直接上单测。

## Implementation Decisions

**契约与数据**

- hagent 对象库 REST adapter 新增项目级 documents 读端点，直出文档注册表（document_id / path / sha256 / doc_type，分页），复用既有服务层查询；鉴权与既有矩阵读端点一致。
- 前端新增两条同源读代理：documents 列表、project workspace 文件内容（后端读文件端点已存在，仅缺代理）。
- 文档注册表随抽屉详情按需载入；文档内容按 document_id 缓存，sha256 作为内容版本键，项目切换时失效。
- `line_span` 语义维持既有契约：1-based 闭区间、指向 OCR 规范化 Markdown 的源文件行号。

**交互（grilling 决策 1、2、7、8、9）**

- 呈现形态：抽屉内对照双栏（左原文面板、右条目列表）；窄屏（视口放不下双栏时，阈值约 <1000px）降级为二级视图（带「返回条目」，返回时恢复列表滚动位置）。
- 触发：来源签点击是唯一触发器。条目行的纯文本来源行、评分表「来源」列均升级为签；每条 ref 一个签。basic_info 卡不动。
- 覆盖：商务/技术条目 + 评分项必做；否决项对象带合法 source_refs 的顺带给签（同一套组件），没有的不显示。
- 高亮策略：全局同一时刻至多一个活跃 ref；点任何签即切换定位与高亮、旧高亮清除；活跃签点亮。面板常驻直到手动关闭或关抽屉。
- 容错分层：注册表缺 document_id → 签置灰不可点 + 悬停说明；文件读取失败 → 面板内错误态 + 重试；line_span 缺失/越界 → 照常打开文档、顶部黄条「未能定位」、不滚动不高亮。坏数据必须可见，不静默吞掉（与「提取需人工核验」的产品立场一致）。

**渲染（grilling 决策 3、4、5）**

- 渲染态 Markdown + 块级高亮：渲染管线保留源码 position，把源行号锚点标注到块级元素上；与活跃 ref 的 line_span 相交的块整块高亮（命中单行 HTML 大表格即整表高亮）。语料含单行内联 HTML 表格，管线需支持 raw HTML 块。
- 排版取文档预览原型页（Archive 品牌「文档预览与导出」）的层级密度（h1/h2 衬线标题、正文 14px/1.75、全边框表格），颜色映射到 Frost token；**文档字体保留原型衬线栈，并为原文面板破例引入 Web 字体**（破例范围严格限定在溯源预览面板），CLAUDE.md「零 Web 字体」硬约束条目与 frost-design skill 需同步加注记。
- 高亮视觉：系统蓝浅染 + 左缘蓝条（蓝 = 交互语义），不占用橙/红警示色。

**动效（apple-design 原则 × Frost 约束）**

- 实现载体遵守仓库约定：gsap，不手写 CSS keyframes；只动 transform 与 opacity。
- 时长与缓动遵守 Frost 档位：micro 120ms / float 200ms / panel 320ms，标准缓动 cubic-bezier(.32,.72,0,1)；无任何无限循环动效。
- 可打断（apple-design 首要原则）：抽屉加宽与面板滑入过程中不锁输入；重定向动画一律从当前呈现值出发（gsap 对同一属性的新 tween 覆盖旧 tween），杜绝跳变。
- 空间一致性：原文面板从抽屉左缘滑入、退出走原路，进出缓动互为镜像；加宽与滑入编排为同一次连续动作（材质「到场」而非纯淡入），与既有抽屉入场（scrim 淡入 + 面板滑入）的语言一致。
- 高亮出现用一次性的短暂强调（染色淡入，micro 档），滚动定位用平滑滚动；`prefers-reduced-motion` 下全部动效与平滑滚动退化为即时切换（既有抽屉已有此分支，延续同一判定）。
- 反馈在指针按下即时给出（签的按压态），不等 click 完成。

**状态归属**

- 活跃 ref、双栏开合、文档载入态放抽屉层局部状态/context，不进全局 workspace store——SSE 事件批处理是 store 的性能关键路径，低频 UI 态不去搅动它。文档内容缓存与注册表除外（跨抽屉开合复用，进数据层）。
- 溯源纯逻辑（签可用性判定、源行号→渲染块映射、容错分层判定）收进 lib 层纯模块，组件只消费。

## Testing Decisions

- 好测试只测外部行为：REST 用例经 TestClient 打真路由，断言响应形状、分页语义、404/鉴权行为，不 mock 服务内部。
- 后端：documents 端点用例加进既有 REST adapter 测试文件（prior art：矩阵 overview/items 端点的既有用例风格）；document registry 服务层已有专门测试，不重复覆盖。
- 前端：不引入测试框架（本迭代收口决策）。质量门维持 `pnpm typecheck`（strict + noUncheckedIndexedAccess）+ `pnpm lint`；溯源纯逻辑收 lib 纯模块保持未来可测性。
- 验收走实跑：起 hagent（8000 端口）+ 前端，上传 `data/` 真实语料跑完解析，驱动「点签 → 加宽双栏 → 定位高亮 → 多签切换 → 三类容错态 → 窄屏降级 → reduced-motion」全路径。

## Out of Scope

- basic_info（项目概要）卡的溯源（时间线节点、分包的 source_refs 不升级）。
- 文档查看器作为画布实体（线框方案 D）；条目行内联摘录气泡（方案 C），包括「在全文中查看」类兜底。
- 从原文反向定位条目（反查）、原文标注/划线。
- 多文档并排对照；PDF/DOCX 原件预览（只渲染 Markdown 转换产物）。
- 长文档虚拟化渲染（语料约 1700 行/篇，整篇渲染可承受；确有性能问题另开票）。
- 溯源缺失条目的定向重抽/修复流程（恢复仍走对话）。
- 无 source_refs 的否决项的任何溯源兜底。

## Further Notes

- SSE 消息契约不受影响：本特性只新增 REST 读路径，不碰消息解析与渲染（无需动 SSE 手册）。
- Web 字体破例是对全局硬约束的有意修订，实现票需包含 CLAUDE.md 与 frost-design skill 的注记更新，避免后续评审误判违规。
- 评分卡详情当前以表格列呈现来源（仅第一条 ref），升级为签时顺带解决「多 ref 只显示第一条」的信息丢失。
- 抽屉焦点圈（Tab 循环）现由抽屉组件自管，双栏加宽后新增的可聚焦元素自然纳入既有循环，无需新机制；Esc 关闭语义不变（先关面板还是直接关抽屉由实现权衡，倾向 Esc 一步关抽屉、面板关闭走显式按钮）。

## 形态改版：预览层取代对照双栏（2026-07-28）

Status: shipped

原双栏形态上线后暴露三个问题，用户从核验者视角提出重设计：Markdown 渲染不完整（公式与部分表格没出来）、排版不像渲染后的文档、预览区太窄。核对语料后三条都成立，且第一条的破损程度比表面严重。

### 被取代的决策

- **「抽屉内对照双栏 + 窄屏二级视图」→ 盖满画布的预览层。** 双栏留给原文的版心只有 ~503px，而公文纸面排版（原型 `.page`：720px 纸面 + 72/80px 白边）与招标文件宽表格（前附表 4 列长中文、语料最宽 9 列）都要 720px 以上——**版心不够是排版做不出来的硬原因，不只是观感问题**。工作台是单列布局（对话是画布上的浮层），画布级浮层几乎能拿到满窗宽度。随之删除 `.is-trace` 加宽、`.cv-trace-secondary` 二级视图、`DUAL_MIN_WIDTH` 三套分支与票05 的「加宽 + 滑入」transform-only 编排。
- **Esc 语义从「一步关抽屉、不分层退面板」改为「逐层退」**（先退层、再关抽屉）。两层浮层下单步语义会让用户无法只退阅读层。判定收在 CanvasDrawer 的单一 window 处理器（同节点上 stopPropagation 拦不住彼此的监听器）。
- **`$…$` 从「OCR 噪声，如实按文本呈现」改为经 KaTeX 渲染。** 原判断只对了三分之一：语料里约三分之二是合法算式（`$20 \%$`、`$\textcircled{1}$`、`$7{\times}24$`、`价格得分 $=$`），KaTeX 渲染正确；其余是引号被误识别成哥特体上标的 OCR 讹误，渲染后内容仍错但远比裸 LaTeX 可读。
- **手写块分段器 + 手写 JSX 渲染器 → unified 真管线。** 根因：MinerU 的 `<table>` 单元格正文含硬换行，而旧分段器只在「每行以 `<` 开头」时继续吞 HTML 块，于是一张表被切成未闭合残片 + 一堆带**字面量 `</td><td>`** 的段落。实测全语料 69 张表破 17 张（25%）、52 行泄漏标记到可见正文。`rehype-raw` 用真 HTML 解析器接管后一并修好，且 hast 节点原生 `position` 直接给出块级行号，比手写分段器更准。

### 故事级影响

| 故事 | 变化 |
|---|---|
| 5 核验与落状态同一视野 | **保住** —— 对照条内嵌 `ItemActions` |
| 6 多条来源逐一点跳 | **变好** —— 层内来源步进器走完，不用退层再找签 |
| 19 像读公文一样读 | **变好** —— 真管线 + 纸面排版，公式与跨行表格终于成型 |
| 20 窄屏二级视图 | **取代** —— 预览层自适应，二级视图删除 |
| 26 面板从左缘滑入、原路退出 | **改写** —— 改为浮层淡入 + 轻缩放，进出仍镜像 |
| 12 面板常驻、切换条目不收起 | **降级** —— 层盖住列表，跨条目切换需先退层；层内只做同条目多来源步进 |
| 24 双栏打开时过滤签与锚点照常工作 | **降级** —— 过滤签在层后，需先退层 |

12 与 24 是本次形态改动的真实代价。若要补，路子是在对照条上再加「上一条 / 下一条条目」步进，但本次不做——会把预览层变成第二个条目浏览器，超出「把原文看清楚」的范围。

### Web 字体口径（补充原破例条目）

KaTeX 结构样式必须引入（它把 `.katex-mathml` 裁成 1px，否则 MathML 与 HTML 会把同一公式渲染两遍），但它自带 9 个 KaTeX_* 字族 / 20 个 woff2（1.2MB）。**「零 Web 字体」不为算式开第二次口子**：字族在 globals.css 里被覆盖成文档字体栈，`@font-face` 只有真被用到才下载，因此一个字形文件都不会被请求。只覆盖 `font-family`，KaTeX 的间距与上下标位移照旧生效。原有的正文衬线破例（Newsreader + Noto Serif SC）不变。
