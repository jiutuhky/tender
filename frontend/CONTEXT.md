# CONTEXT —— 产品前端

工作台画布(大纲视图)相关的领域词汇表。只收术语,不收实现细节。

## 画布

- **双模式**:真实工作区默认显示项目结果或未上传空态；演示模式仅从 `/workspace?demo=1` 明确进入，示例产物与真实项目隔离。
- **应答矩阵卡**:真实模式下的四张核心制品卡——项目概要(basic_info)、商务应答矩阵(business)、技术应答矩阵(technical)、评分办法(scoring)。数据来自应答矩阵槽位。
- **主轴卡(大纲卡)**:mockup 里的「投标文件大纲」骨架卡。仅属演示模式;真实模式不出现(真实大纲未来由矩阵生成,登场时另立实体)。
- **结果概览**:真实工作区的默认阅读视图，四类结果按原尺寸卡片排列，可纵向滚动；消息窗展开时在桌面预留左侧空间。商务与技术卡显示人工核验进度。
- **中心舞台**:切换至画布视图后，解析进行期间四卡以 2×2 四宫格呈现。全盘失败时定格于此。
- **停靠列**:矩阵生成完毕后,四卡沿画布最左侧自上而下(概要 → 商务 → 技术 → 评分)垂直排列的终局位置。 仅适用于可选的画布视图；默认概览不缩放内容。
- **停靠(编排)**:从中心舞台飞往停靠列的一次性程序接管动画。只在亲历解析的浏览器会话中播放;恢复/刷新路径直接以停靠态呈现,不重放。停靠后卡位完全归还用户。
- **生成完毕**:四个矩阵槽位全部到达终态(ready 或 error)的时刻,是停靠的触发信号;与对话流是否收尾无关。
- **终态**:矩阵槽位的 ready 或 error 状态。error 计入终态,不阻塞编排。
- **解析中断**:流异常终止且存在未到终态的槽位时,卡面呈现的状态。区别于「解析中」(仍在进行)与「解析失败」(槽位 error)。

## 对话浮层

- **Prose Bot 消息窗**:画布左上角承载智能体执行流的浮动窗口。两档——**min**(Bot + 一行[[播报]],无玻璃底,transcript 已卸载)与 **open**(404px 玻璃面板,完整执行流)。位置固定不可拖拽。min 态发送消息或解析出错时自动展开。 初始采用 min 档，提交任务时展开。
- **Bot(锚点)**:消息窗左上角常驻的品牌形象(app icon 的拟人化身)。**两档里它的绝对坐标完全一致**,窗口从它右下方生长——这是整个开合交互的支点,也是唯一的开合控件(播报文字与 caret 不可点)。
- **播报**:min 档的那一行状态。由**新活动行到达**驱动推进(新旧两条上下滚动交接),不是定时轮播;文案与[[活动条]]同源。
- **输入坞**:画布底部居中的浮动输入区。上方一行是**快捷指令**(有项目时才出现,点击预填输入框、不代发),运行期由活动条顶替。
- **活动条**:运行期浮在输入坞正上方的一行状态,报智能体此刻在做什么(如「正在提交矩阵条目 · 技术应答 · 4 次调用」),点击展开消息浮窗。它订阅的是派生字符串而非时间线,内容不变即不重渲。
- **材质分工(Frost)**:能打字的地方实底(Composer),只报状态或做快捷入口的地方走玻璃(活动条、快捷指令)。**例外(2026-08 消息窗改版)**:执行流正文直接落在玻璃上,窗内不再套第二个面——代价是思考块时间线竖线改为按项分段画(原先靠图标的 `var(--surface)` 不透明外环遮断,在半透明面上会留白饼),实底元件一律换半透明填充(用户气泡除外,它是有意为之的实色标记)。
- **边框光束**:open 档运行中沿窗框旋转的一段亮弧(注册 `@property` 的角度驱动 conic 渐变,stroke / inner / bloom 三层)。与 Bot 光晕、扫描眼同属「进行中」动效,状态一结束立即停。
- **执行流毛玻璃**:消息窗 open 档由 `LiquidGlass` 提供单层中央散射、主题底色、方向性高光和分层投影，圆角为 28px。
  1. 中央散射使用 `blur(8px) saturate(125%)`，通过相交渐变遮罩向边缘淡出；正文处于独立内容层。滤镜的标准属性和 WebKit 前缀在 JSX 内联声明，确保构建后生效。
  2. 玻璃祖先保持正常合成，开合只淡入淡出正文。精确鼠标指针下光位小幅响应，每帧合并更新装饰层的 transform。
  3. 减少动效时停用光位跟随；减少透明度、高对比度、强制颜色时使用主题实底并隐藏玻璃装饰层。
  4. 消息窗开合从当前显示尺寸与内容透明度接续，支持中途反向；落定在 min 后卸载正文。圆角与窗口外壳保持一致，Bot 在两档中位置一致。
- **浮层渲染边界**:`WorkspaceChrome` 以稳定的 memo 边界承载消息窗、执行看板和输入坞。它们通过各自的 Zustand 订阅更新，画布相机裁剪、选择和布局变化只更新画布；项目切换沿用工作台的挂载周期。
- **画布点阵**:中性底色上铺设低对比度网格点，间距和偏移复用 `useCanvasViewport` 的平移、缩放变量；低倍率自动放大间距，保持清晰。

## 卡面与详情

- **卡面四行语法**:画布矩阵卡以题名、主指标、结构条与信号行为基础。默认概览使用原尺寸卡片、明确的进入箭头，并补充商务与技术的核验进度；不依赖悬停传达可点击性。
- **主指标**:卡面唯一的大字(27px/600 tabular)。数字扛信息,后缀退三级灰。概要卡取剩余天数,招标文件未写明投标截止时降级到预算。
- **结构条**:分类构成压成一条 4px 堆叠条(此前是四行分类条形图,12 个元素)。段色走中性灰阶(深→浅 = 多→少),第五类及以后并成浅色尾;没有结构可画时整条不渲染,不留空轨道。概要卡的那条是投标窗口(最早节点 → 截止)的已过 / 剩余两段。
- **信号行**:色点作扫描锚、**数字**扛语义色,句子本身保持中性——一张卡只该有一个最响的元素(主指标),信号行是次响。至多两项,风险信号优先于分类注释。
- **状态只在偏离常态时发声**:终态不发标签(卡面出现数字本身就是「已生成」);进行中 = 卡顶一根发丝线 + 题名行「正在解析」;失败 / 中断 = 卡壳左缘一根色条(橙 / 灰)+ 卡面一句直陈。基调由 `matrixCardBadge` 的 `tone` 派生,是这条规则的唯一落点。
- **提示语汇(通则)**:警示、错误、质量提示一律**不做彩色填充块、不立彩色边线**——浅色语义底加一根圆角竖条读作便利贴,不读作提示。语义色只落在**图标与标题**上(红=否决/废标一类致命内容,橙=需注意但可恢复),条文与说明照常用主色 / 二级灰;分区交给 hairline 与留白,秩序交给中性 tabular 序号。落点:详情否决项(`.cv-det-veto`)、提取质量提示(`.cv-det-notice`)、卡面失败与中断(`.cv-face-fail`)、溯源层的未定位与读取失败(`.cv-trace-banner` / `.cv-trace-error`)五处共用这一套。
- **决策触发器**:每张卡面预览必须亮出的、驱动用户「要不要点开细看」的关键信号——截止时间(概要)、实质性条款数(商务/技术)、高风险条目数(技术)、分值结构(评分)。四项在[[卡面四行语法]]里一项不少,只是换了更轻的说法。
- **实质性条款**:招标文件中带 ★ / mandatory 标记、不满足即废标的条款。UI 中恒用橙/红系警示色——★ 沿用招标文件的原生记号(`.cv-star`),高风险等其余警示走「色点 + 文字」(`.cv-mark`),都不做药丸。
- **抽屉详情**:点卡后从右侧滑入的完整视图,是「展开详情」的唯一形态。标题与摘要只在标题栏出现一次(正文不再自带 SecTitle);条目分组用分组眉 + hairline 列表,不套边框卡(抽屉自身已是一个面,再套就是三层盒子);条款原文默认两行,按**实测**是否被截断决定给不给「展开原文」。 默认宽度上限 760px，可切换「专注核验」扩展为整块工作面。
- **人工动作**:条目行与原文对照区中的核验确认、应答状态标注，均直接落对象库并保留版本冲突反馈。操作常驻可见，触屏点击目标至少 40px；保存失败保留原有状态并显示就地错误。商务与技术列表支持全量搜索、待核验筛选和每页 50 条分页。

## 溯源预览

- **溯源预览（原文工作面）**：来源签打开画布内的独立阅读面；桌面以原文为主、右侧对照条目，窄屏默认单栏阅读，通过「对照」打开核验区。底层详情保留位置，Esc 逐层退出，焦点限制在当前预览层。
- **对照区**：右侧呈现条目编号、标题、原文位置和要求正文，独立滚动；应答状态及核验动作固定在区底。确认和应答判断各自保存，以控件状态呈现结果，保存失败就地提示。
- **核验导航**：对照区顶部箭头按条目顺序前后查看；「确认并继续」保存当前核验后进入下一条待核验要求，「跳过」保留当前待核验状态。已核验条目可用「继续核验」寻找下一条待核验要求，保存失败或预览已关闭时不自动前进。
- **原文位置**：同一条目在同一文件内的多处引用按页码合并展示，直接点击页码跳转；多文件来源通过标题栏的文件选择器切换。未定位的引用明确保留其状态，避免把其他引用当作该处位置。
- **原文页面**：PDF.js 连续分页阅读，默认按舒适版心适配；页码与缩放集中在底部工具条。离开引用区域后出现「回到引用」，收起对照区和缩放时保留当前阅读位置。历史 Markdown 文档保留线性纸面阅读。
- **来源签**：由 `source_ref(document_id + line_span)` 触发原文预览；行号属于给模型读取的只读 Markdown，通过同版本 sidecar 转换为原页区域。
- **活跃 ref**：点击的引用决定首次定位；阅读器同时呈现当前条目在同一文件中的所有可定位区域，通过页码直接选择阅读位置。
- **高亮选区**：PDF 使用版面块级半透明区域，跨页表格分别高亮各页；打开时定位点击的引用，随后可直接按页码切换。映射版本、几何或行号失效时照常阅读原件并提示未定位。历史 Markdown 仍按渲染块与行号相交高亮。
- **文档注册表**:hagent 侧 document_id → workspace 文件路径(含 sha256)的项目级映射,溯源预览解析来源签的依据。
- **溯源动效语汇**:预览层入场 = 遮罩淡入 + 面板 scale .98→1 到位(只动 transform / opacity);退场取镜像,缓动用 Frost 标准曲线的镜像控制点(1,0,.68,.28)——镜像曲线是标准缓动对可逆过渡的合法延伸,常量收在 canvas/traceMotion.ts。**到场让位**保留:缓存命中时整篇文档会在入场途中 commit,长帧会冻住动画,所以浮层落位前持骨架。
- **Markdown 渲染管线**:`lib/trace/pipeline.ts` 的 unified 管线(remark-parse / gfm / math → remark-rehype → **rehype-raw** → rehype-sanitize → rehype-katex → 行号锚点)。三处顺序是刻意的:`rehype-raw` 用真 HTML 解析器接管 MinerU 表格(其单元格正文含硬换行,早期按「每行以 < 开头」吞 HTML 块的手写分段器会把一张表切成未闭合残片 + 一堆带字面量 `</td><td>` 的段落——全语料 69 张表破 17 张、泄漏 52 行);`rehype-sanitize` 必须在 `rehype-katex` **之前**(净化对象是语料里的 HTML,KaTeX 自己产的 MathML 是可信产物,洗掉就丢了无障碍标注);行号锚点必须最后,且**只打 root 层子节点**——打到嵌套节点会把整块高亮碎成片。行号取 hast 节点原生 `position`,与 line_span 同坐标系。
- **公式呈现**:`$…$` 经 KaTeX 渲染(反转了早期「OCR 噪声,如实按文本呈现」的决策)。语料里约三分之二是合法算式(`$20 \%$`→20%、`$\textcircled{1}$`→①、`$7{\times}24$`→7×24),其余是引号被误识别成哥特体上标的 OCR 讹误,渲染结果内容仍错但比裸 LaTeX 可读。KaTeX 结构样式必须引入(它把 `.katex-mathml` 裁成 1px,否则 MathML 与 HTML 会同一公式渲染两遍),但其 9 个 KaTeX_* 字族在 globals.css 里被覆盖成文档字体栈——**「零 Web 字体」不为算式开第二次口子**,20 个 woff2 一个都不会被请求。

## 提交与能力边界

- **附件暂存**:首页与工作台统一先选择文件、移除或补充要求，明确提交后再创建项目。当前支持 PDF 与 Markdown 招标文件，Ctrl / ⌘ + Enter 提交，Enter 换行，输入法组合期间不提交。
- **失败恢复**:文件提交失败保留内存中的文件与要求，重试复用已创建的项目和会话；执行中断后先重新加载结果，或恢复要求供用户判断是否重发。不声称能停止后端任务。
- **项目地址**:创建成功后工作台 URL 携带项目 ID；刷新恢复已发布结果，历史消息尚未恢复。
- **截止时间**:按文件时区计算；缺时区明确标注「按北京时间」。纯日期不推断截止时刻，当日已过明确时刻显示「已截止」。
- **能力边界**:项目页与首页使用同一真实项目读端点；知识库暂未开放真实资料服务，示例资料需主动进入；文档预览是明确标注的排版示例；登录入口不收集未接入认证服务的账号密码。
