# 0007. 项目工作区与沙箱租约：workspace 归 Project，VM 按 Run 租用

- 状态：已接受
- 日期：2026-07-10
- 关联：[调研文档 2026-07-09](../research/2026-07-09-agent-project-session-sandbox-workspace-lifecycle.md)、hagent spec [2026-07-10-project-workspace-design.md](../../hagent/docs/specs/2026-07-10-project-workspace-design.md)（本 ADR 的实施契约）、smolvm spec D6（被本决策升级）、ADR 0004（共享结构入库与本决策合流）

## 背景

产品语义：一个标书 Project 绑定一次投标工作，产物与工作区应跨会话共享、持续演进（类比 Claude Code 中 repo 与 session 的关系）。现状错位：smolvm sandbox 与 workspace 均绑 session，session 之间互为孤岛，没有稳定持久层（文件只活在 VM 磁盘与一次性 DISK 快照里）；前端每次上传新建 project + session 一一对应。同时画布交互要求**项目内多个节点 Agent 并行生成**（章节级 fan-out），并行不是远期能力而是核心交互。

两轮调研（2026-07-09 落盘 + 2026-07-10 交叉验证 Manus/Claude Code/Cowork/Codex/Devin/Replit/Lovart 及 E2B/Modal/Fly 基础设施层）结论一边倒：**没有任何主流产品让 Project 绑定一台长生命周期共享可写沙箱**；共识结构为「项目级模板与持久状态层 ↔ 会话/任务级一次性沙箱 ↔ 外置持久层（git/产物库/记忆）」；凡存在共享主状态，写入要么被串行化成独占窗口（Replit Applying、Codex Apply、Manus 人工审批），要么用 append-only 消解（Lovart 画布）。

## 决策

**Project 绑定逻辑工作区（canonical workspace），物理 VM 是按需租约。**

1. 每个 Project 一个宿主侧持久目录 + host 侧 git 仓（`sources/ structured/ deliverables/`），是唯一事实来源；创建 Project 即建工作区，**不建 VM**。
2. VM 租约绑**活跃 Project**（非 session、非常驻）：项目内第一个 Run 触发租用，所有并行 Run 与会话共享同一台；闲置降档/回收沿用；VM 死亡 = 换台重物化，项目无损。smolvm spec D6「会话绑数据不绑 VM」升级为「**项目绑数据，Run 租算力**」。
3. 执行单元升格为一等实体 `Run`（对话轮 = `chat_turn`，节点生成 = `node_generation`），锁、checkpoint、SSE、审计统一挂 Run；Session 回归纯对话容器。
4. 每个 Run 的 SSE 流结束（正常/异常/打断三路归一）即增量 checkpoint（guest 变更检测 → 下载 → host git commit），生命周期时点（pause/快照/evict/release）强制兜底；全量回写 + 排除名单（`tmp/` 等）。
5. 并发按领域分区而非大锁：节点 Run 启动登记名下路径，文件工具层对被锁路径拒绝；对话轮之间互斥；共享结构（响应矩阵/大纲树）按 ADR 0004 入库行级更新；git commit 操作短互斥。
6. DISK 快照降级为 project 键的 best-effort 唤醒缓存，恢复失败静默冷启动 + 注入，不再承担持久化职责。

派生变更：上传文件归属 project（`sources/`，支持补遗追加）；会话必须归属 project；resumeProject 改读 project workspace；dev 阶段旧 session 数据不迁移。

## 备选与否决理由

- **Project 绑定常驻共享 sandbox**（原始提案）：语义直观，但物理 VM 成为业务身份——池上限 4 台 = 4 个活跃项目打满宿主；VM 故障/宿主重启升格为项目级事故；并行会话共写一块盘互踩；长命 VM 漂移成不可复现雪花机。业界零先例。已否决，仅在「活跃项目共享一台租约 VM」这一层保留其直觉的合理内核。
- **维持 session 绑定 + 仅产物入库**：改动最小，但「跨会话持续演进的工作区」这一产品语义仍然缺失，用户无法确定哪个 session 是最新版。已否决。
- **每节点 Run 独立 VM + 隔离副本 + 合并**（Replit 同款）：隔离最强，但受池容量约束（单项目 fan-out 即超容），且把合并/冲突 UI 提前到 MVP。推迟到多机容量与协作需求出现后再议。
- **纯目录 + manifest（无 git）**：MVP 最简，但 Phase 2 的 revision/diff/合并要重造粗糙 git。已否决，host 侧 git 增量成本仅一个 commit 调用。

## 后果

- 用户核心诉求兑现：同项目多会话共享持续演进的工作区；`git log` 即项目演进史，Run.base_revision → commit_sha 天然可审计。
- 丢数据窗口收敛为「正在执行的一轮」；VM/快照全链路失败均不再是数据事故。
- 引入 runs 表与三层锁（对话轮互斥、节点路径锁、commit 互斥），复杂度集中在 hagent server 层；文件工具层新增路径锁检查点。
- sessions 表的 sandbox 系列字段迁往 project 级租约状态，属破坏性 schema 变更（dev 阶段直接迁移，不做兼容）。
- 实施分三期（M1 工作区上移 / M2 Run 实体化 / M3 节点并行），契约细节见 hagent spec `2026-07-10-project-workspace-design.md`。
