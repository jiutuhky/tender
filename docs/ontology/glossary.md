# 本体层术语表

ADR 中首次引入的新术语在此登记（约定见 [`docs/adr/README.md`](../adr/README.md)）。产品面用语遵循 frost-design 的采购语域；「动态本体」相关词汇仅限内部与融资 / 技术材料（ADR 0006）。

## 本体总则

| 术语 | 定义 | 出处 |
|------|------|------|
| 本体层 | 平台的领域对象 + 链接 + 动作三元模型；内部架构词，不对客户使用 | ADR 0001 / 0006 |
| 语义层 | 本体中的对象与链接（描述「有什么、怎么关联」） | ADR 0002 |
| 动力层 | 本体中的 Action（描述「允许发生什么变更」）；智能体只能经此写业务对象 | ADR 0002 |
| Action 网关 | 动力层的实现：schema 校验 + 审计日志 + 可选人工确认的唯一写入口 | ADR 0002 / 0004 |
| 本体模块 | hagent 内承载本体的独立模块（自有 router + Action 网关 + 对象表） | ADR 0004 |

## 对象与链接

| 术语 | 定义 | 出处 |
|------|------|------|
| 需求项（RequirementItem） | 商务 / 技术要求条目，含强制项标记与偏离风险；源自应答矩阵 | 现有矩阵 schema，升格于 ADR 0004 |
| 评分项（ScoringItem） | 评审办法逐条拆解，含分值、评分规则、强制门槛 | 同上 |
| 应答章节（ResponseSection） | 投标文件大纲节点与正文载体；Phase 2 启用，schema 首发留位 | ADR 0001 |
| 证据资产（EvidenceAsset） | 业绩案例、资质证照、人员简历等机构级可引用资产；Phase 3 启用 | ADR 0001 / 0004 |
| 覆盖（链接） | 评分项 → 需求项 的挂接关系；评分沙盘的骨架，本体独有资产 | ADR 0005 |
| 应答（链接） | 需求项 → 应答章节 的响应关系；Phase 2 启用 | ADR 0001 |
| 引用（链接） | 应答章节 → 证据资产 的引用关系；Phase 3 启用 | ADR 0001 |
| source_refs | 对象到招标文件 Markdown 原文的行级溯源（document_id + line_span） | 现有矩阵 schema |

## 重解析与身份

| 术语 | 定义 | 出处 |
|------|------|------|
| 对齐迁移 | 重解析后新旧对象按稳定逻辑 id 匹配（行号重叠 + 文本相似度），确认与链接按置信度三路分流 | ADR 0003 |
| 待复核 | 条款文本实质变更时旧人工确认的保留态——不静默迁移、不作废，进裁决队列 | ADR 0003 |
| 裁决队列 | 待确认 / 待复核 / 偏离裁决的人工处理队列；UI 落位为侧抽屉 | ADR 0003 / 0005 |
| 变更影响清单 | 澄清补遗文件触发对齐迁移后，一键生成的条款变更影响汇总 | ADR 0003 |

## 呈现层

| 术语 | 定义 | 出处 |
|------|------|------|
| 评分沙盘 | /workspace 画布主视图：以评审办法组织的评分表骨架，评分项展开显示挂接需求项与三态 | ADR 0005 |
| 覆盖三态 | 覆盖 / 待裁决 / 缺口——沙盘唯一的状态词汇；明令禁止分数预测 | ADR 0005 |
| 状态带 | 沙盘头部的仪表条（强制项 N/N · 评分覆盖 M/M · 待裁决 K） | ADR 0005 |
| 裁决抽屉 | 裁决队列的常驻右侧收纳形态，点状态带「待裁决」展开 | ADR 0005 |
| 废标警示 | 强制项门槛未全部通过应答时沙盘顶部的红色警示条 | ADR 0005 |

## 归属与命名空间

| 术语 | 定义 | 出处 |
|------|------|------|
| org_id | 对象表的机构命名空间列；单租户填默认机构，只进 schema 不进首发 UI | ADR 0004 |
| 默认机构 | 登录 / 多租户体系落地前，org_id 的占位机构 | ADR 0004 |
