# CONTEXT —— Agent 后端

Agent 后端相关的领域词汇表。只收术语，不收实现细节。

## 结构化资产

- **结构化资产**：一次投标 Project 内生的、受管理面治理的结构化工作产物——应答矩阵、偏离表、大纲等。区别于 workspace 里的普通项目文件：不以文件为事实来源，一切创建与变更经由管理面进行（2026-07-13 起的设计主线）。
- **管理面**：结构化资产的唯一写入口。agent 经 MCP 工具面接入，人经产品界面接入；两路汇于同一服务做校验、审计与并发裁决。
- **对象库**：结构化资产的唯一事实来源存储。读写均经管理面；MCP resources 不承载对象数据，只放契约文档，对象的查询式读取走只读工具。
- **document registry**：招标源文件在管理面的注册表（路径 + 哈希 + 文档类型 → 文档 ID）。源文件本体仍是 workspace 普通文件；registry 是结构化资产源引用（line_span）与保真校验的锚点。
- **导出投影**：结构化资产按需物化出的文件形态（如偏离表 Excel、喂给下游生成流程的临时 JSON）。只读、可再生，不回写。
- **应答矩阵**：从招标文件抽取出的四类源引用回溯矩阵——项目概要（basic_info）、商务（business）、技术（technical）、评分（scoring）。首发唯一受管对象域。
- **偏离表**：矩阵条目「应答状态」（完全响应/正偏离/负偏离及说明）的投影视图，不是独立实体；不存在矩阵之外的偏离行。
- **草稿区**：抽取产物的暂存态。worker 逐批提交记录、合并与修复均发生于此；未发布前对下游不可见。
- **发布**：草稿通过全部质量校验后晋升为当前版的动作。是抽取的完成门禁并留下 revision 快照点，**不是**定稿封存——发布后矩阵仍是活对象，行级变更持续可审计。
- **增量维护**：补遗/澄清文件的默认处理方式——不全量重抽，由 agent 逐条 add/update/drop 现有矩阵条目，人工状态天然保留。全量重抽仅作逃生门，触发时明示丢弃人工状态。
